## 三层责任

| 时间（北京时间，每日含周末） | 行为 | 完成依据 |
|---|---|---|
| 09:40 | 原任务采编 | 当日 digest、daily、daily-report，既有质量审计及发布 |
| 11:30 / 15:30 / 21:30 | 独立 GitHub Actions 检查 | 日期、文件、卡片编号、审计状态以及四个公开数据文件一致 |
| 11:40 / 15:40 / 21:40 | 原任务的限次补跑 | 已交付则跳过；缺发布只修发布；缺内容接续已读材料 |

11:30为交付检查截止，不是承诺调度平台准点运行。GitHub 定时可能延迟；同日三轮及手工入口降低单次漏跑影响。同一 Codex 对话只允许一个 heartbeat，所以补跑并入原自动任务，不新建研究对话。最多三次补跑机会，不创建自循环。

## 状态与证据

- `scheduled` / `running-window`：未到11:30，不称已完成。
- `overdue`：到期缺文件、日期、卡片，或仍为兜底标识；fail。
- `publish-pending`：本地产物已存在，线上内容未匹配；到期 fail。
- `quality-blocked`：审计或一方断链存在明确阻断；fail。
- `publication-unverified`：网络等原因无法验证；warn，不能称成功，云端运行保持失败告警。
- `published-gap`：仅缺口记录已发布；warn，仍保留补跑 Issue。
- `published`：当日三个内容文件与线上版本一致，线上信息 manifest 日期和卡片数匹配，无明确质量阻断。质量为 warn 可以发布，但不改为 pass。

回执在 `data/info-delivery-status.json`，人类摘要在 `operations/info-delivery-latest.md`。自动化聚合和系统健康显示交付状态。回执不是内容价值证明，也不能证明某台机器曾运行任务；旧日回执不得复用于今日。

## 独立告警

`Info Delivery Watchdog` 不采编、不生成兜底日报、不改历史内容、不下载PDF。无论研究失败、检查异常或 git push 失败，均尝试保留 Actions 附件与同日唯一补跑 Issue；再次运行只更新同一 Issue。成功核对后关闭该日 Issue。GitHub 的邮件/客户端通知由用户订阅设置决定，不能保证必达。

状态文件采用明确白名单提交，失败状态也必须可被公开部署。工作流与既有专题兜底共用并发锁，避免两条云端任务同时写回；和本地提交发生竞态时保留失败与附件，不覆盖正文。

电脑离线时，云端仍可发现和记录遗漏，但当前没有云端正式研究执行器，不会自动生成有质量的日报。恢复在线后由原任务接续；若要无人值守的云端研究，需要另行配置研究运行环境及预算。本机制不宣称这一能力已经具备。

## 补跑与停止规则

先检查当日产物，不把 git 干净、子代理结束、昨日功能测试或上游扫描完成当作交付。保留已读来源及原始证据，接续而非从头搜索。无可信新增就诚实记录覆盖与缺口，不以昨天内容改日期、堆卡片或专题占位满足检查。

常规发布后运行 `node scripts/check-info-delivery.cjs`。仅检查当天三份内容及公开信息 manifest，不做全站重复检查。部署等待最多三次有界重试，仍不一致就报告具体失败步骤，保留告警，等待下一个既定补跑机会。

本次验收只证明交付兜底能识别9月11日遗漏，不等于已补齐9月11日内容。
