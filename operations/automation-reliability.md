# 自动化可靠性机制：每日情报任务

## 目标

每日情报任务不能再依赖某一台电脑是否在线。正式交付采用“两层机制”：

1. **本地正式交付**：Codex 自动化 `automation` 每天 18:00 在 `/private/tmp/ODIC-current` 产出四专题日报、一份总览、HTML 阅读页，并推送到 GitHub Pages。这是正式研究链路。
2. **上游信息扫描**：Codex 自动化 `automation-3` 每天 08:30 维护私有组织情报扫描，`od-intelligence-center-daily` 每天 09:40 维护公开信息库、PDF 入库和首页信息流。这是日报的素材来源。
3. **云端兜底交付**：GitHub Actions 每天固定运行，只负责不断档、生成缺口记录、覆盖审计、知识库同步和分享能力；它不能替代正式多代理研究。

- `automation-3`：继续作为每日 08:30 的上游私有组织情报扫描，不直接替代 OD 情报中心专题日报。

## 已固化的工程约束

- GitHub Actions 不只确保当天，还会回看最近 4 天，补齐周末、假期或网络波动造成的缺口。
- 每天 18:20、21:30、次日 09:30（Asia/Shanghai）都触发云端守护，避免单个 cron 漏跑。
- 周一 18:45 增加周报守护，保证周报入口不会因为周末缺本地任务而断档。
- 覆盖审计会写入 `specials/ai-org-talent-mechanism/quality/coverage-latest.md`，缺失日期和非决策稿会被显式列出。
- 首页不得把兜底稿标成正式报告；缺证据时必须显示“待正式重跑 / 非决策稿”。
- 覆盖审计和质量门禁可以标红、失败和记录债务，但 GitHub Actions 兜底提交不应因此完全中断；否则会再次出现“任务没完成、缺口也没记录”的黑箱状态。

## 运营规则

- 第一优先级是每天必须完成正式研究任务：四专题日报、总览、HTML 阅读页、首页入口、同步推送。
- 第二优先级才是质量门禁：正式日报必须满足新增事实、Context、反例/冲突信息、招聘 JD 与薪酬信号、来源索引和主代理交叉验证。
- 兜底稿的价值是“不断档、可追责、可补跑”，不是替代正式研究；兜底稿不得进入首页日报分区冒充正式更新。
- 如果本地深度研究没有跑，第二天必须优先重跑缺口日期，再进入当天日报。
- 每天 18:00 后的运维判断顺序：先看 `automation` 是否产生正式 `auto-sync`；再看 `od-intelligence-center-daily` 是否更新信息库；最后看 GitHub Actions 是否只留下兜底状态。
