# 自动化可靠性机制：每日情报任务

## 目标

每日情报任务不能再依赖某一台电脑是否在线。正式交付采用“两层机制”：

1. **云端强制交付**：GitHub Actions 每天固定运行，确保当天和最近 4 天的日报入口、HTML 页面、周报入口、质量审计和知识库同步链路不缺档。
2. **本地增强交付**：本地 Codex/WorkBuddy 继续负责深度联网研究、多代理交叉验证和 CEO 决策稿重跑；如果本地未执行，云端产物必须明确标记为“待正式重跑 / 非决策稿”。

## 根因记录

2026-05-30 至 2026-05-31 周末期间，GitHub 云端兜底任务成功运行，但没有本地 `auto-sync` 提交。说明问题不是 GitHub Pages 部署失败，而是正式研究链路仍依赖本地执行环境；当本地电脑离线、休眠、网络异常或自动化未触发时，只剩兜底稿。

## 已固化的工程约束

- GitHub Actions 不只确保当天，还会回看最近 4 天，补齐周末、假期或网络波动造成的缺口。
- 每天 18:20、21:30、次日 09:30（Asia/Shanghai）都触发云端守护，避免单个 cron 漏跑。
- 周一 18:45 增加周报守护，保证周报入口不会因为周末缺本地任务而断档。
- 覆盖审计会写入 `specials/ai-org-talent-mechanism/quality/coverage-latest.md`，缺失日期和非决策稿会被显式列出。
- 首页不得把兜底稿标成正式报告；缺证据时必须显示“待正式重跑 / 非决策稿”。

## 运营规则

- 兜底稿的价值是“不断档、可追责、可补跑”，不是替代正式研究。
- 正式日报必须满足：新增事实、Context、反例/冲突信息、招聘 JD 与薪酬信号、来源索引和主代理交叉验证。
- 如果本地深度研究没有跑，第二天必须优先重跑缺口日期，再进入当天日报。
