# 信息库滚动更新接管说明

> 生效日期：2026-05-26  
> 适用范围：首页「信息库」页签、`digest.md`、`daily/`、`daily-report/` 以及由这些文件驱动的来源覆盖、条目卡片和每日信息流。

## 一句话结论

情报中心、专题项目和知识库分开治理、定期互相回流：情报中心负责广谱前沿信息获取，专题项目负责深度研究和证据升级，知识库负责长期沉淀和复用。Codex 接手的是 WorkBuddy 已经跑通的高密度信息流运营工作，而不是把信息库降格为专题日报摘要。

## 已确认的现状

- 页面呈现：`index.html` 在前端读取 `./digest.md`，通过 Markdown 解析生成首页「信息库」卡片。
- 数据主文件：`digest.md` 是首页信息流的唯一直接数据源；`daily/YYYY-MM-DD.md` 和 `daily-report/YYYY-MM-DD.md` 是每日原始记录与日报追溯材料。
- 历史生成机制：WorkBuddy 项目说明记录了 4 个信息搜集自动化，分别覆盖国际媒体、国内媒体、咨询学术、社交搜索，并在 17:00 生成日报；这是后续 Codex 运营必须继承的最低生产方式。
- 历史同步机制：`sync.sh` 检测工作区变更后自动 `git add -A`、生成 `auto-sync` 提交并推送到 GitHub。
- 风险点：接手后若只做专题判断、不复刻多渠道采集和信息卡密度，信息库会从“前沿情报流”退化为“少量观点摘要”；这是必须修复的核心问题。

## 三层治理边界

| 层级 | 目标 | 主要产物 | 与其他层的关系 |
|---|---|---|---|
| 情报中心 | 持续看见 OD、AI、未来组织、企业案例、人才机制、招聘薪酬和社媒/公众号前沿信号 | `digest.md`、`daily/`、`daily-report/`、信息库周报、信息库月报 | 给专题项目提供线索和事实入口 |
| 专题项目 | 围绕四个课题做深度研究、互证、反例检验和决策判断 | `specials/ai-org-talent-mechanism/` 日报、周报、基线档案 | 从信息库取材，把高价值判断回流信息库和知识库 |
| 知识库 | 把报告、PDF、公众号文章、企业案例和方法论沉淀成可复用知识资产 | `knowledge/` 结构化条目、PDF 入库卡、概念页 | 为信息库和专题项目提供长期上下文 |

三者不是互相替代关系。当同一材料同时有信息价值、专题价值和知识价值时，必须分别处理：信息库保留事实卡片，专题项目提炼证据判断，知识库沉淀结构化摘要。

## 后续责任边界

| 模块 | Codex 责任 | WorkBuddy 责任 |
|---|---|---|
| 信息库滚动流 | 负责复刻并提升 WorkBuddy 的高密度信息卡生产方式：多渠道采集、条目质量、去重、可信度、来源覆盖、页面可读性、每日交付稳定性 | 可提供历史样式、历史数据、本地草稿、摘录、资料搬运 |
| `digest.md` | 正式写入和发布前需满足字段完整、来源可追溯、结论不夸大、与 OD/AI/未来组织相关 | 历史格式作为信息卡标准样本 |
| `daily/` | 作为每日信息流原始记录，必须保留高质量信息卡密度，不得被专题日报替代 | 可继续沉淀基础资料 |
| `daily-report/` | 作为每日可读版追溯材料，保留日报但不替代信息库信息卡 | 可作为过程记录 |
| 信息库周报/月报 | Codex 负责按周、按月聚合信息密度，提炼趋势、冲突、案例和下周期追踪问题 | 可调用历史材料辅助聚合 |
| 知识库 | Codex 负责把高价值报告、PDF、公众号文章、案例结构化入库 | WorkBuddy 可做资料整理、搬运和基础文档管理 |
| 专题/周报/基线 | Codex 负责研究质量、证据升级、反例和行动建议 | 不承担最终交付 |

## 每日多渠道代理协议

每日信息库采集必须并行覆盖至少四类渠道，并由主代理交叉验证：

1. **官方/一手材料代理**：公司官网、新闻稿、博客、IR、SEC、政策文件、产品文档、官方白皮书。
2. **权威媒体与案例代理**：Reuters、FT、WSJ、The Information、Bloomberg、36氪、虎嗅、机器之心、晚点、财经媒体和企业案例报道。
3. **咨询/学术/报告代理**：McKinsey、BCG、Bain、Deloitte、Mercer、Gartner、WEF、OECD、MIT、Stanford、HBR、AIHR 等。
4. **社媒/职场/公众号代理**：LinkedIn、Reddit、Hacker News、脉脉、知乎、小红书、微信公众号「AI组织进化论」和同类垂直号。
5. **招聘 JD 与薪酬信号代理**：公司招聘页、LinkedIn Jobs、Levels.fyi、Payscale、薪酬报告、岗位说明和技能溢价信号。

主代理职责不是把五路信息简单拼接，而是完成去重、互证、证据分层、反例标注和 OD 机制翻译。

## 日报、周报、月报机制

| 周期 | 定位 | 最低交付要求 |
|---|---|---|
| 日报 | 捕捉层：尽可能不漏前沿信号 | 正常日保留 8-15 条高价值信息卡；低信息日也要说明扫描范围、缺口和弱信号，不得用空泛内容填充 |
| 周报 | 聚合层：把一周信息从流水变成判断 | 固定两版：快速导读版只给结论、关键事实和启发；详细资料版按主题、企业、机制、反例、Context 和线索重组 |
| 月报 | 结构化认知层：把一个月信息沉淀为知识地图 | 按高置信趋势、关键企业案例、组织机制、岗位/职级/薪酬/激励信号、反例冲突、弱信号和下月追踪清单分类 |

数量不是唯一标准，但低数量必须有充分理由。更重要的是事实具体、来源可追溯、与 Jordan 的 OD/AI/未来组织工作强相关，并能说明“提示我们关注什么”。

## 信息库条目准入标准

每条进入 `digest.md` 的信息必须具备：

1. 标题：明确主体、动作和对 OD/组织机制的含义。
2. 事件摘要：说明时间、来源、事实动作，不把判断伪装成事实。
3. 来源：必须有原文 URL；无法访问时标记为线索，不升级为高可信。
4. 来源平台：用于页面来源覆盖统计。
5. 来源可信度：只使用 `⭐高`、`📰较高`、`💬参考` 三档。
6. OD 启示：必须写清“提示我们关注什么”，不能只复述新闻。
7. 标签：用于专题聚合和后续检索。
8. 抓取时间：使用 `YYYY-MM-DD HH:MM`。

## Codex 接管后的运行规则

- 每天至少检查一次 `digest.md` 是否有当日条目、来源字段、可信度字段和 OD 启示字段。
- 信息库条目只作为事实与线索池；日报、周报和基线档案需要主代理二次验证后再升级为结论。
- WorkBuddy 历史产物是信息库质量基准样本；WorkBuddy 或其他工具写入的新增 `auto-sync` 内容需要由 Codex 抽检、修正、去重和补源后才能作为正式情报交付。
- 如果当天没有足够可信新增信息，页面应明确显示缺口，不用低质量内容填满卡片。
- 凡是被日报/周报/专题引用的 PDF 和高价值报告，要同步进入知识库，并提供结构化摘要、相关性和关注点。
- 中文表达必须统一：中文为主，必要英文采用“中文解释 + 英文原词”的方式；不得出现影响阅读的 ABC 体。

- `operations/info-library-status.md`

## 交接后的判断

从 2026-05-26 起，情报中心稳定运营和信息交付由 Codex 负责。这个责任的含义是：Codex 必须继承 WorkBuddy 已经证明有效的多渠道、高密度、信息卡式生产方式，并在此基础上增加质量门禁、交叉验证和周期沉淀；不得把信息库简化为专题日报或少量观点摘要。

## 与四专题日报的边界

- `od-intelligence-center-daily` 每天 09:40 更新的是信息库、PDF 入库、首页信息流和组织情报桥接；它是素材层，不等于四专题日报完成。
- `automation` 每天 18:00 生成的 `specials/ai-org-talent-mechanism/YYYY-MM-DD/` 五份报告才是 AI 时代组织与人才机制四专题正式日报。
- 如果信息库当天有 `daily/` 与 `daily-report/`，但专题目录只有“研究状态记录 / 非决策稿”，页面应视为“素材层已更新、正式日报未完成”。
- 如果 GitHub Actions 只生成兜底记录，Codex 第二天必须先补跑缺口日期，再做当天正式日报。
