# AWS / Amazon

## 实体定位
观察云平台如何把 AI adoption 和 AI 安全组织化的实体锚点。

## 与 AI 组织设计的关系
- AWS FDE 把专家嵌入客户团队，并留下文档、runbook 和 internal champions。
- Amazon AI Red Team 岗位显示 AI 安全进入 Threat Operations 管理建制。

- AWS 支持“FDE / Applied AI 从岗位语言变成客户能力迁移机制”的判断；来源 2026-07-01 digest，L3。
- Amazon AI Red Team 支持“核心专家能力正在管理化”的判断；来源 2026-06-29 digest，L2。
- Fanatics 案例支持“智能体客服应按协调、专业处理、风险识别和人工判断拆分责任”的观察；来源 2026-08-20 digest [D03]，L2，长期结果未验证。
- AgentCore Policy 支持“智能体规则应在执行系统外强制，并把提出、审批、发布和例外责任分开”的观察；来源 2026-08-21 digest [D01]，L2，误拦截和跨会话控制仍待验证。
- Everyone Can Build 支持“AI 能力建设开始从专业岗位扩展到全员原型能力”的 L1 组织意图；来源 2026-08-26 digest [D07]，不能据此判断生产率已经提升。

## 明确边界 / 不能下的结论
- 不能仅凭 AWS FDE 判断其已有完整职业序列、薪酬带宽或晋升路径。
