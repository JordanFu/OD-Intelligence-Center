# OpenAI

## 实体定位
观察企业部署组织和代理式知识工作的实体锚点，不写公司百科。

- Codex：知识工作变成可委派、可执行、可复核的工作包。

## 当前可形成的判断
- OpenAI 的“低 stop energy”更适合解释为在质量、安全、性能和可监督性护栏内下放可逆决策，而不是取消治理；来源 Tibo 跨访谈与 Codex 发布记录，L3。
- Codex 案例支持“执行能力提升后，组织瓶颈迁移到意图、审查、监督和恢复”的判断；L3。
- OpenAI 可支持“客户部署组织成为 AI adoption 接口”的判断；来源 2026-07-01 digest，L3。
- OpenAI 2026-08-19 的公开制度说明支持“安全治理已能影响研发节奏”的观察；来源 2026-08-19 digest [D01]，L2，控制效果尚未独立验证。
- OpenAI 2026-08-20 的公开机制支持“内容控制、风险监测和人工执法可以分权设计”的观察；来源 2026-08-20 digest [D01]，L2，误报与审计效果待验证。
- OpenAI 2026-08-23 的公共立场与公司回应增强“治理从发布末端前移到训练监测、权限削减和暂停恢复”的观察；来源 digest [D01]、[D02]、[D05]、[D06]，L2，但不证明安全团队拥有稳定否决权。
- B2B 产品战略财务岗位支持“收入、算力、容量与边际贡献正在接入同一分析接口”的 L1 岗位信号；来源 digest [D03]，实际到岗、组合损益权和绩效结果未知。
- 数据中心三个岗位共同支持“宽协调责任与深采购、质量专业化并存”的 L1 招聘信号；来源 2026-08-24 digest [D12]—[D14]，不能据此确认净增编制、正式岗位族或运行效果。
- 部署与系统集成岗位进一步支持“宽责任接口、亲自构建型管理者与深专家并存”的 L1 招聘信号；来源 2026-08-26 digest [D11]，不能据此确认团队已按该机制稳定运行。
- 事故复盘支持“高风险研究需要按工作负载授权、暂停和复启”的 L2 观察；来源 2026-08-27 digest [D02]，但新控制的误报、研究延迟和复发率尚未验证。
- 多模态安全产品经理与法律行业 FDE 支持“治理责任产品化、行业交付责任变宽与专业能力深化并存”的 L1 招聘信号；来源 2026-08-27 digest [D11]—[D12]，不能据此确认编制、到岗或通用职业体系。

## 明确边界 / 不能下的结论
- 不能把 OpenAI 的高管公开叙事直接等同于整个组织的实际文化，也不能据此证明该机制在扩大规模和进入高风险行业后仍然成立。
- 不能把 OpenAI 内部 Codex 使用深度外推为普通企业已完成组织重构。
- 不能仅凭 DeployCo 判断 FDE 已有通用职级和薪酬体系。

## 待验证问题
- 核心产品组织中，研究、产品、安全对不同风险等级的正式决策权与升级路径是什么？
- Codex 团队的 review load、回滚、事故恢复和人员负荷长期趋势如何？
- DeployCo 是否形成独立职级、交付评价和资源分配规则？
- Codex 是否改变晋升证据、代码审查责任和 manager 复核标准？
- 最大规模训练恢复门槛、暂停次数和最终否决权能否获得外部核验？
- 私密安全处理的信号字段、申诉流程和独立审计如何设计？
- 私密计算与身份认证岗位的首次发布时间、团队汇报线和责任交接如何？
- SB 53 修法建议是否进入正式文本，并改变 OpenAI 内部训练监测、事故报告和恢复签字链？
- B2B 产品战略财务岗位是否获得折扣、额度、算力容量和资源配置的正式决策权？
- 数据中心采购、跨专业协调和制造质量岗位的编制属性、汇报线、停线/拒收权及宽薪酬带如何解释？
- 数据中心负责人更替后的汇报线、决策权和项目连续性如何安排？
- 部署负责人和系统集成负责人的个人交付、团队建设与跨团队协调如何分别考核？
- 工作负载负责人、安全否决权、复启时钟和事故外部通知责任如何划分？
- 多模态安全产品经理与法律行业 FDE 的汇报线、绩效、薪带映射和晋升证据是什么？
