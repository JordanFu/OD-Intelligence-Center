# LLM Wiki：OD 情报中心知识库运维方法

## 核心原则

OD 情报中心不把知识库当作一次性 RAG 文件堆，而是当作一个可持续演化的 Wiki：

- **Raw Sources 是事实层**：原始文件、网页、PDF、导出资料保持不可变，只做引用和回查。
- **Wiki 是编译层**：由 LLM 将来源拆解为概念、实体、案例、对比和方法论页面。
- **Schema 是治理层**：规定目录、命名、标签、摄入、查询、健康检查和发布规则。

## 与页面运维的关系

页面端只展示“已编译、可读、可追溯”的知识，不直接堆原始文件。每个卡片至少回答：

1. 这是什么资料或概念？
2. 为什么与 OD / 组织设计相关？
3. 它支持或挑战了哪些已有判断？
4. 下一步应如何追踪或使用？

## 三类知识资产

| 层级 | 内容 | 页面呈现 |
|---|---|---|
| Source | 报告、文章、书籍、内部资料、Obsidian 原始笔记 | 知识库卡片 + 阅读器 |
| Concept | AI 原生组织、技能为本组织、能力价值、绩效管理等 | 概念卡片 + 关联案例 |
| Synthesis | 日报、专题、横向对比、判断更新 | 专项页 + 日报页 |

## 运维动作

- **Ingest**：读取新资料，写入摘要页，更新 `catalog.json`、`index.md` 和 `log.md`。
- **Query**：先读索引，再读相关 Wiki 页面，输出有引用的综合回答。
- **Lint**：定期查孤立页面、过时判断、矛盾结论、缺少来源的强判断。

## 当前采用的具体规则

- 日报必须保留“结论层 / Context 层 / 线索层”。
- 知音楼、Obsidian、网页资料进入页面前，必须先被转成可读摘要。
- 不可访问或未验证的资料只放“入口/待摄入”，不伪装成已读结论。
- 知识库页面优先展示主题、来源、状态、下一步动作，而不是只展示文件名。
