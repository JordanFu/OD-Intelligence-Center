# Agentic SDLC：智能体时代的软件交付操作模型

## 一句话判断

Agentic SDLC 不是让 AI 多写代码，而是把软件交付从“人类主导、AI 辅助”重连为“人类监督、Agent 执行”的交付操作系统。

## 核心变化

传统 SDLC 的大量损耗发生在需求、设计、编码、测试之间的人工转译。Agentic SDLC 试图把功能描述、非功能需求、护栏规则、架构约束和测试标准转成机器可读输入，让 Agent 在端到端 pipeline 中执行，人类在关键闸门做监督。

一个典型图景是 24 小时循环：夜间 Agent 工厂生成需求解析、架构检查、设计方案、初版代码和测试报告；白天人类审核结果、处理风险、补充业务约束、与法务/合规/设计等角色对齐，并为下一轮 Agent 执行准备更好的输入。

## 四个前提

- 业务方能清楚表达“要建什么”和“为什么重要”。
- 技术环境标准化，架构、框架和模块边界足够清晰。
- 需求、约束、设计和验收标准能结构化表达。
- 核心干系人参与整条价值链，而不是把 AI 交付当作工程团队内部工具。

## 对组织设计的含义

- 团队会从大规模职能分工转向更小的 cross-functional pod。
- 工程师角色从“实现者”转向“系统监督者、质量判断者、知识图谱维护者”。
- 产品、设计、法务、合规和安全会更早进入交付链，因为 Agent 执行前需要更清晰的约束。
- 技术组织的核心资产会从文档堆积转向可被 Agent 使用的知识图谱、测试体系和工作流协议。

## 绩效与人才影响

Agentic SDLC 会放大“会定义问题、会写约束、会验收质量”的人才价值。只看代码量或任务数的绩效指标会迅速失真，组织需要转向业务影响、系统质量、可维护性、风险控制和 Agent 编排能力。

## 风险边界

如果业务输入模糊、架构债务严重、测试体系薄弱，Agentic SDLC 会加速混乱。它要求组织先把隐性知识、质量标准和流程边界显性化。
