# 2026-08-26｜专题三：岗位、族群、序列的持续建设

> **证据窗口**：2026-08-25 18:00—2026-08-26 18:00（Asia/Shanghai）。本文区分 ATS 页面、招聘需求、批准编制、实际到岗、岗位、岗位族与职业序列；同一公司同一 ATS 的多张页面先合并为一个来源族。**页面数 ≠ 需求数 ≠ 编制数 ≠ 净增人数 ≠ 到岗人数；公开报价 ≠ 内部薪带；外部标题 ≠ 内部级别。**

## 读者应该带走什么

- 今天没有高置信的新岗位族或职业序列制度。OpenAI、Perplexity、Harvey 的公开 ATS 只把“目标责任、外部标题、公开报价”照亮了一小块，证据上限为 L1—L2 页面事实。
- 三个来源族同时提示一种值得继续验证的组合：客户／伙伴／部署岗位的责任包在变宽，安全、系统集成、模型平台和数据平台等控制责任在变深；两种运动可以在同一家公司、同一生产系统中并存。
- Perplexity 用 MTS 这一粗颗粒外部标题覆盖研究、Agent Harness 与 Model Platform，Harvey 又公开区分 Senior—Staff 且薪酬区间重叠。这说明“外部标题压缩”与“内部专业差异、复杂度分级”并不矛盾，但今天还不知道三家公司真实的内部映射。
- 业务提出“建一个 AI 新序列”时，先判断它是在解决长期责任、技能识别、市场稀缺、阶段攻坚、持续风险责任还是关键人才保留。多数问题可由技能标签、稀缺系数、项目激励、专项／临时津贴或薪带调整更轻地解决。
- 今日裁决：可以启动一个责任包试点和 ATS 版本审计；不批准新族群或新序列。

## 1. 今日一句话专题判断

AI 时代的岗位架构不是单向“去专业化”，而是**端到端执行责任变宽、关键控制责任变深、外部标题可能变粗、内部评价与定价仍需变细**；今天的 ATS 信号增强了这一假设，却不足以把招聘页面升级为企业岗位族、职业序列或晋升制度。

## 3. 今日核心判断

### 判断一：责任包变宽与控制岗位深化并存，而不是二选一

- **可信度：中。**
- **证据基础**：OpenAI 的部署／伙伴岗位覆盖从识别、编排、采用到商业与复盘的端到端结果，同时保留安全架构、系统集成和技术运营责任；Perplexity 的 Agent Harness 与 Model Platform、Harvey 的 Data Platform 专家级别也指向深技术控制。当天证据均是招聘意图，历史 8/21—8/25 正式稿和内部岗位族基线提供跨日复现，但仍无运行结果。
- **为什么重要**：如果只强调“复合型”，容易把生产、验证、批准、审计合到一人，制造自我验收；如果只强调“专业化”，又会把接口切碎。岗位架构应同时设计结果 owner、专业控制 owner、独立验收人和事故／恢复 owner。

### 判断二：外部标题压缩不等于内部等级、专业轨和薪酬差异消失

- **可信度：中低。**
- **证据基础**：Perplexity 用 MTS 覆盖三种不同专业责任；Harvey 则公开 Senior—Staff，且两个薪酬区间重叠。二者只证明公开页面呈现不同，不能确认内部 level mapping、同岗同级或跨轨规则。
- **为什么重要**：企业可以用较少外部 title 降低身份壁垒，但内部仍需保留复杂度、错误后果、专业签字、影响范围和市场定价的可审计差异；否则“去头衔”会演变为隐形等级和经理自由裁量。

### 判断三：岗位架构的最小单位应是“稳定结果＋正式权力＋错误后果”，不是技能词或工具名

- **可信度：中高（历史机制增强，今日增量弱）。**
- **证据基础**：今日 ATS 可读到不同的目标责任，却没有制度证据；内部知识库的岗位族基线连续要求用结果对象、决策权、质量／风险和长期工作量区分岗位。Perplexity 同一 MTS 下出现多种技能，再次说明标题或技能词本身不够。
- **为什么重要**：用“AI”“Agent”“Prompt”等词直接造岗位，会随技术版本快速过时；以结果、权力和后果定义责任包，技能可以更新而岗位架构不必频繁重建。

### 判断四：关键人才的市场溢价，不应自动转译为新岗位或晋升

- **可信度：中。**
- **证据基础**：Harvey 的 Senior 与 Staff 公开报价重叠，说明薪酬并非仅由外部 title 决定；昨日 Pave／Nua 供应商报告也提示研究、平台和应用集成人才有不同现金、股权与流失曲线，但不是企业制度。今日没有实际录用、拒绝、留任或内部公平数据。
- **为什么重要**：业务提“新序列”有时是在为少数关键员工争取定价空间。先用同岗同级市场数据判断稀缺，再选择稀缺系数、薪带、股权刷新或阶段激励，避免把短期议价固化成永久制度债务。

### 判断五：今天应明确“不新建序列”，但要保留可逆试点

- **可信度：高（证据边界判断）。**
- **证据基础**：三家 ATS 均未公开岗位编码、三级复杂度、正式薪带、进入／转序、晋升、校准、申诉、退出和旧岗映射；窗口内咨询、学术和社媒也没有补齐这些字段。
- **为什么重要**：无证据时直接建序列，最难撤销；可逆的责任包试点、技能标签和阶段激励既能满足业务速度，又为后续制度化积累真实数据。

## 4. 重点案例事实还原：三种公开岗位呈现，不能拼成一种成熟职业架构

### 4.1 背景

AI 原生公司需要同时把研究／模型能力变成可靠系统、客户结果与商业增长。外部招聘页是观察责任设计的低成本窗口，但其目的首先是吸引候选人，而不是披露内部组织制度。OpenAI、Perplexity、Harvey 因此适合做“责任假设对照”，不适合作为可照搬的制度标杆。

### 4.2 时间线

1. **8/25 20:17—8/26 09:58**：OpenAI ATS 先后展示风险技术运营、广告解决方案负责人、学习产品、实验室／系统集成、安全架构、部署与伙伴岗位。
2. **8/26 04:42—12:31**：Perplexity 的三个 MTS 页面进入 ATS feed；同一 ID 的公开标题在晨间记录和 18:09 截面之间出现变化。
3. **8/26 04:39—07:39**：Harvey 展示 Legal Engineer 和 Data Platform Senior／Staff；地域重复页使用相同描述与报价。
4. **8/26 18:09**：复扫确认页面仍可见，但没有取得任何一家内部岗位架构、批准编制或到岗数据。

### 4.3 动作

- **OpenAI**：用部署、伙伴与亲自下场型管理岗位承接跨职能结果，同时公开招聘安全、风险、系统集成等专业责任。
- **Perplexity**：以 MTS 为共同外部 title，再用括号中的 Researcher、Agent Harness、Model Platform 区分责任领域。
- **Harvey**：对数据平台公开显示 Senior—Staff 专家级差和重叠报价；另设 Legal Engineer 连接法律专业、客户与产品反馈。

这些是页面上表达的招聘目标，不等于公司已经“实施”了相应组织动作。

### 4.4 可能机制

三种呈现可能共同服务于一个设计逻辑：外部 title 保持简洁，内部按价值对象分工；靠近客户的角色对端到端结果负责，靠近关键瓶颈的专家对标准、可靠性和复杂系统负责。真正可运行的内部架构至少还需要：

`结果对象 → 正式决策／签字权 → 复杂度级差 → 质量与风险证据 → 市场参照 → 横向流动／晋升 → 校准与申诉 → 退出`。

公开 ATS 只覆盖这条链中的前半段，因此机制仍是假设。

### 4.5 已知结果

- 可核结果仅是页面字段：标题、职责、地点、公开报价、唯一 ID 与当前 `publishedAt`。
- Harvey 的 Senior／Staff 报价区间重叠；Perplexity 三个 MTS 页面责任不同；OpenAI 同时呈现宽责任和深专业页面。
- **没有**组织成效、到岗、绩效、留任、内部流动、晋升、薪酬公平或客户结果可核。

### 4.6 争议与阻碍

1. ATS 的 `publishedAt` 可能表示发布或再发布，不等于岗位首次创建；Perplexity 同一 ID 改标题说明页面会变。
2. 地域复制、同描述页面和一个 requisition 的多人招聘会扭曲页面计数；Harvey 的四页只对应两个工程级别呈现。
3. 招聘文案可能把理想职责写得很宽，却没有相应权力、资源和评价标准，容易形成“责任扩张、授权不足”。
4. 薪酬区间受地点、级别、供需与股权结构共同影响，不能凭重叠区间推断等级失效，也不能用上限给内部普调。
5. 三家公司均缺内部员工视角、正式制度与后效数据，不能互相“拼接”成一套完整最佳实践。

### 4.7 可借鉴点

- 外部 title 可以少而清晰，内部责任矩阵必须细；title 与 level 分开治理。
- 用端到端结果定义部署／伙伴岗位，用标准、可靠性、恢复和错误后果定义专家深度。
- 对每个招聘页面保存唯一 ID、首见时间、标题／职责／报价版本与关闭状态，避免把页面漂移误读为组织变化。
- 专家级差不要只写年限，要写系统跨度、不可逆决策、专业签字、他人放大和资产复用。

### 4.8 不可照搬点

- 不复制 MTS、Legal Engineer、Technical Deployment Lead 名称就宣布建立新族群。
- 不把三家同用 Ashby 当成三家制度互证，也不把多页换算为编制或到岗。
- 不把公开报价直接搬成内部薪带，不因 Senior／Staff 区间重叠取消等级。
- 不让宽责任岗位同时生产、验收、批准与审计，也不让深专家只剩身份溢价而无正式责任。

## 5. 背景材料与 Context 层：弱信号、反例与冲突信息

> **暂不形成结论，但提示我们关注……**AI 岗位可能正在形成“外部称谓更少、内部责任接口更多”的结构；要判断它是降低身份壁垒还是把等级转入黑箱，必须取得内部 level mapping、实际权力、薪带、跨轨流动与晋升校准数据。

- **字节产品线收敛是旧线复核，不是今日岗位重构。**团队归属、统一汇报和产品入口的公开线索可提示“集中决策＋保留专业产品边界”，但组织动作在窗口前；没有岗位编码、人员、职级、薪酬和后效，不能写成新族群、去岗位化或减层。
- **腾讯匿名回应提供反例边界。**公司相关人士否认“新建 400—500 人 AI 游戏部门”，只称既有 AI 引擎部长期招聘。这说明部门名称、传闻人数和平台能力不能替代组织图、服务目录、预算与岗位架构；该回应仅 L1。
- **Holly 只证明产品控制点可以被描述。**岗位分类、薪酬、审批留痕进入同一产品，并不证明客户形成新 HR／AI 岗位或分类公平改善。
- **Tibo 能力—产品转换回路是历史机制综合。**它支持研究与产品共享结果、可逆决策下放和监督容量同步增长，但底层材料跨 2021—2026，不能冒充 8/26 新岗位制度。
- **直接晋升制度新增仍为零。**Harvey 的级别和报价、Perplexity 的 title、OpenAI 的责任描述，都不能替代晋升材料、评委、校准、申诉与晋升后效。

## 7. 行动启发｜对我们的启发：用最小充分机制承接真实问题

### 管理层该问

- 业务要的是长期不同的责任和职业市场，还是只想为少数关键员工解决当期价格、项目和保留问题？

### 7.1 先过六道门

| 决策门 | 通过标准 | 不通过时 |
|---|---|---|
| 结果与权力 | 存在区别于现岗的稳定结果，以及明确的建议、批准、否决、暂停、恢复、验收或事故责任 | 更新现岗责任包与接口，不新增岗位 |
| 持续性 | 工作跨 18—24 个月、至少两个业务周期，有稳定预算和退出假设 | 用项目激励、专项／临时机制 |
| 评价独立性 | 能用独立产出、质量、风险与复用证据评价，不靠工具使用量或主管印象 | 用技能标签、权限认证、项目证据 |
| 规模与接替 | 有复数在岗人员、第二人覆盖、文档、移交与故障接管 | 单人先用稀缺系数或阶段机制 |
| 专业内核与市场 | 跨至少两个团队长期复用，有共同能力内核、人才来源与横向流动 | 保留单一岗位或技能标签 |
| 架构闭环 | 能定义三级复杂度、薪带、进入／转序、晋升、校准、申诉、退出和旧岗映射 | 坚决不新增序列 |

### 7.2 九条并列路由

| 真实问题 | 优先路由 | 触发条件、期限与退出 |
|---|---|---|
| 新技能但结果责任未变 | **技能标签** | 绑定真实项目、质量、权限和 6—12 个月复证；技能失效或不用即撤销。 |
| 同岗同级出现稳定市场稀缺 | **市场稀缺系数** | 用实际录用／拒绝、流失、地区与级别数据校准；年度复核并设封顶、退出。 |
| 从零到一建设、迁移或攻坚 | **项目激励** | 按里程碑、质量与独立验收结算；项目结束即退出。 |
| 长期承担值守、合规、隐私、安全、签字或停线责任 | **专项津贴** | 权力与负荷可核，6—12 个月复核资格；责任取消即停止。 |
| 短期代理、试点兼任、过渡负担 | **临时补贴** | 写明起止、负荷上限、转正式门槛和恢复原岗条件。 |
| 同一岗位价值长期系统偏移 | **薪酬带宽调整** | 使用同岗同级、地区、现金／股权、实际授予和公平性数据；不直接搬 ATS 上限。 |
| 独立结果与正式权力成立，但规模不足 | **新岗位** | 先运行两个评价周期，配置第二人、移交与并回条款。 |
| 多个同构岗位共享专业内核和人才市场 | **新族群** | 至少两个团队、复数在岗、共同能力模型、评价与定价证据。 |
| 独立专业需要长期定级、定价、晋升和人才再生产 | **新序列** | 三级复杂度和完整架构闭环缺一不可；今日不满足。 |

### 7.3 何时坚决不新增

出现以下任一情形，不新增岗位；申请族群／序列时，关键条件缺失即退回：

1. 去掉“AI”“Agent”“自主”等词后，结果对象、权力和评价证据均未改变。
2. 只有一个试点、客户、项目或不足两个业务周期的临时工作量。
3. 只有 ATS 页面，需求性质、批准编制、实际到岗和长期工作量未知。
4. 生产、验证、批准与审计由同一人承担，存在自我验收。
5. 没有第二人、文档、系统归属、故障接管、移交和退出日期。
6. 技能标签、稀缺系数、项目激励、津贴、补贴或薪带已经能解决真实问题。
7. 主要理由是竞品 title、关键员工议价或供应商市场数字，而非本企业责任证据。
8. 无法建立三级复杂度、薪带、校准、申诉、流动、退出与旧岗映射。

### 7.4 未来 30 天最小试点

选择一个真实 AI 工作流，先做一条纵向切片：

`业务结果 → 现岗责任变化 → 专业控制／独立验收 → 技能与权限 → 市场数据 → 最小激励路由`

30 天只记录周期、合格率、返工、人工接管、专业复核时数、异常／恢复、单点风险和员工负荷。只有稳定责任通过六道门，才进入新岗位评审；不提前批准族群或序列。
