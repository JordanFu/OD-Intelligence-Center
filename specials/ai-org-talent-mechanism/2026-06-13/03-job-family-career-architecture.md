# 2026-06-13｜专题三：岗位、族群、序列的持续建设

## 1. 今日一句话专题判断

今天岗位/族群/序列最值得确认的新变化是：**AI 时代许多岗位变化不该先翻译成新 title，而应先翻译成更清晰的 competency bundle、scope bundle 和 invisible-work bundle。**

3. **arXiv《Beyond the Org Chart》指出，AI 影响的不只是 formal role responsibilities，还包括跨角色协作、专业反馈网络与成长体验。**  
   - 来源：arXiv

   - 来源：内部知识库

## 3. 今日核心判断：3-5 条，每条注明可信度、证据基础、为什么重要

1. **AI 时代很多岗位变化的第一语言应该是 competency bundle，而不是 new title。可信度：高。**  
   - 证据基础：AI-native SE 的九维能力模型；Workday 的 task-to-agent mapping。  
   - 为什么重要：title 变化滞后且刚性强，而能力与任务映射更新速度更快。
2. **岗位包里必须开始显性纳入 invisible work。可信度：中高。**  
   - 证据基础：`Beyond the Org Chart` 对 mentoring、professional interaction 和成长体验的发现。  
   - 为什么重要：若岗位定义只写可见产出，不写反馈、带教、校准和跨团队协作，实际高价值劳动会长期失真。
3. **真正适合新建序列的，仍是长期、稳定、稀缺、可评价、可定价的能力域。可信度：高。**  
   - 证据基础：内部 skills-based organization 方法论；近期 role continuum 研究。  
   - 为什么重要：这给“什么时候建序列、什么时候只加 skill tag”提供了硬边界。
4. **业务提出“新岗位”时，真实诉求常常是 scope 和价格，而不一定是结构。可信度：中高。**  
   - 证据基础：技能为本组织方法论；EY 的 skill premium 治理框架。  
   - 为什么重要：很多需求更适合由 capability band、market premium、专项津贴承接。

## 4. 重点案例事实还原：AI-native competency model 为什么不等于“再建一个 AI 序列”

- 背景：组织看到 AI-native engineering 等新概念时，最容易采取的动作是再造一批新岗位名称。
- 论文提供的事实：  
  - 系统综述 48 篇已验证研究；  
  - 将未来能力归纳为 intent、collaboration、verification 三大框架；  
  - 进一步细化到 specification、critical evaluation、agent orchestration、metacognition 等九维能力。  
- 这说明了什么：  
  - 变化首先发生在能力结构；  
  - 岗位边界变得更像“能力组合 + 责任范围 + 质量责任”的动态包。  
- 对岗位/族群/序列的含义：  
  - 先定义更宽的 family，例如 AI-enabled engineering / product / ops family；  
  - 在 family 内用 capability band、scope、decision rights、verification burden 做区分；  
  - 再判断是否需要稳定的新专家序列。  
- 什么时候适合新建正式序列：  
  - 能力长期稳定；  
  - 在组织中反复出现；  
  - 有独立产出物与评价标准；  
  - 市场存在持续定价逻辑。  
- 什么时候只适合用 skill tags / role package：  
  - 能力变化快；  
  - 大量复用现有 family 的底层技能；  
  - 更像某阶段项目或新工作方式，而非长期职业容器。  
- 不可照搬点：  
  - AI-native software engineering 的能力框架不应机械外推到所有职能，但其“先能力后 title”的方法对多数知识岗位都适用。

## 7. 对我们行动的启发

1. 先用 family + capability band + scope + verification burden 设计岗位，再决定是否需要新序列。  
2. 新岗位申请必须回答四个问题：是否长期、是否重复、是否可评价、是否可定价。  
3. 把 mentoring、quality gate、cross-team orchestration 这些 invisible work 写进岗位能力而不是默认存在。  
4. 当真实诉求是稀缺定价或阶段性战役，优先使用 skill premium、项目激励、专项津贴或带宽调整。
