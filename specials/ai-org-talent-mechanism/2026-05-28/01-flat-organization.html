2026-05-28｜专题一：AI时代组织扁平化与中层减少

1. 今日一句话专题判断

当 agent 既能“行动”（不再只给建议）又能穿透 legacy UI 执行旧流程时，组织默认的 人类 gatekeeping 会变成规模化瓶颈：扁平化的关键不再是改组织图，而是重写“谁能发起动作、谁来审批、异常如何升级、谁对结果负责”的运行规则，把大量中层协调劳动迁移到 可执行的工作流 + 可审计的控制面 + 项目负责制（动态 owner）。

2. 今日新增事实（可追溯）

  • McKinsey 于 2026-05-11 发布文章《How agentic AI challenges four rules your organization runs on》，指出多数组织默认“四条运行规则”（只有人能行动、流程按顺序推进、领导应掌握答案、绩效只评估人），并认为 agentic AI 会使这些默认规则失效。来源：https://www.mckinsey.com/capabilities/people-and-organizational-performance/our-insights/the-organization-blog/how-agentic-ai-challenges-four-rules-your-organization-runs-on
  • Microsoft 于 2026-05-26 发布 Copilot Studio 更新，宣布 computer-using agents 正式 GA，并推出新的 workflows 体验、agent-to-agent 通信、Work IQ 互操作等能力，强调 agent 可通过 UI 操作网站/桌面应用以覆盖没有 API 的旧系统流程。来源：https://www.microsoft.com/en-us/microsoft-copilot/blog/copilot-studio/new-and-improved-computer-using-agents-a-new-workflows-experience-and-real-time-voice-experiences/
  • SAP 于 2026-05-15 发布 sustainability AI agents，覆盖监管准备、碳足迹优化、包装合规、GHS 分类与标签、工作场所安全等流程，并披露多项效率改进数据。来源：https://news.sap.com/2026/05/autonomous-enterprise-new-sustainability-ai-agents/
  • Cloudflare 于 2026-05 发布公告《Cloudflare Embarks on a New Chapter: An Agentic AI-First Operating Model》，宣布将转向 agentic AI-first operating model，并表示该转型使约 1,100 个岗位“已不再需要”。来源：https://cloudflare.net/news/news-details/2026/Cloudflare-Embarks-on-a-New-Chapter-An-Agentic-AI-First-Operating-Model/default.aspx
  • Freshworks CEO 于 2026-05-05 发布员工信《Important changes to set up Freshworks for our next phase of growth》，披露将减少员工规模并“remove management layers”、集中部分职能、减少项目，并强调用 AI 自动化/提升效率。来源：https://www.freshworks.com/company/newsroom/important-changes-to-set-up-freshworks-for-our-next-phase-of-growth/
  • 《中国企业家》（由中国经济网转载）于 2026-05-22 报道腾讯 WXG 推行“项目负责制”等组织调整信号（以媒体口径为准）。来源：http://www.ce.cn/cysc/newmain/yc/jsxw/202605/22/t20260522_39397167.shtml

3. 今日核心判断（3-5条）

  1. 扁平化的“真因”不是成本，而是组织默认规则与现实能力不匹配。可信度：高。

- 证据基础：McKinsey 直接点名“只有人能行动/绩效只评估人”等默认规则将失效；Microsoft 把 agent 的执行边界推进到“无 API 的旧系统”；SAP 把政策嵌入可执行流程。

- 为什么重要：只要组织仍以“人类 gatekeeping”为唯一控制点，就会在 agent 规模化时出现审批拥堵、跨部门对齐成本飙升、以及“谁负责”灰区扩大。

  1. 中层减少不等于“管理消失”，而是管理从“管人/管沟通”迁移为“管规则/管例外/管审计”。可信度：中高。

- 证据基础：SAP 把政策从文本变为工作流约束；Microsoft 提供 workflow 设计器与 agent-to-agent 协作；这会把组织矛盾推向“规则 owner/override owner/异常升级路径”。

- 为什么重要：扁平化后若不建立规则与例外机制，中层协调劳动会以“临时会议、微信群对齐、邮件批示”形式回潮，最终又长回层级。

  1. 扁平化的稳定单元更像“项目负责制/动态 owner”，而不是固定小组与固定汇报线。可信度：中。

- 证据基础：腾讯 WXG 报道中的“项目负责制”信号，和全球“workflow 变成可执行系统”的趋势一致：责任越来越围绕“目标与结果链路”而非“固定层级头衔”。

- 为什么重要：动态 owner 能把责任与资源接口绑在同一条结果链上，是扁平化后维持问责与速度的关键组织元件。

  1. “AI 促扁平化”容易被误读为“裁掉管理者就等于升级”，需要把组织动作与能力底座拆开评估。可信度：中高。

- 证据基础：Cloudflare/Freshworks 的公开材料包含裁撤与效率叙事，也包含 operating model 转向与 AI 自动化叙事；二者在真实组织中常同时发生。

- 为什么重要：对标时若只学“减人/减层”，不学“规则/例外/审计”与“流程 owner”设计，内部落地会在 3-6 个月内反噬（质量/合规/交付不确定性上升）。

4. 重点案例事实还原（Freshworks：以“去层级 + 集中化 + AI 自动化”进入下一阶段增长）

  • 背景：Freshworks 在公告中强调进入“下一阶段增长”需要更清晰的聚焦、更少的管理层级与更高的效率，并明确提及 AI 自动化。
  • 时间线：

- 2026-05-05：CEO 发布员工信披露组织调整与人员减少计划。

  • 动作（组织层）：

- Remove management layers（减少管理层级）。

- 集中/整合部分职能与职责（centralize select functions）。

- 减少项目、聚焦更少的优先事项。

  • 动作（机制层）：

- 将效率改进与 AI 自动化绑定：用 AI 和自动化提升运营效率，减少协调劳动与重复劳动。

- 以“更少项目 + 更清晰责任”配合减层，降低跨层对齐成本。

  • 结果（已披露/待披露）：

- 已披露：组织调整方向与管理层级减少的公开口径。

- 待披露：具体减少了哪些层级/岗位、管理跨度变化、审批链与决策权如何重写、以及对交付周期/客户指标的影响。

  • 争议与阻碍：

- 减层后若缺少明确的例外升级与决策权分配，容易出现“责任下沉但权力不上移”的过载。

- AI 自动化引入后，审计/安全/合规边界需要同步明确，否则将把风险外包给一线。

  • 可借鉴点：

- 先用“聚焦更少项目”缩小对齐面，再减层；并把 AI 自动化作为减少协调劳动的关键抓手。

  • 不可照搬点：

- 若企业没有工作流与控制面基础设施，直接压层级可能只是把协调劳动转为更隐性的同步成本，并让关键风险点无人 owner。

5. Context 层（暂不形成结论，但提示关注）

  • 暂不形成结论，但提示我们关注：扁平化与“政策执行型 agent”会让合规/审计变成组织运营的一部分。SAP 的 sustainability agents 展示了政策可直接阻断不合规动作；这会强迫组织回答“谁拥有规则、谁批准 override、谁对阻断造成的业务后果负责”。
  • 暂不形成结论，但提示我们关注：管理者角色可能出现两极分化：一类转型为“规则 owner/系统 owner”，另一类被自动化与组织压缩挤出；但目前公开材料还缺少可复原的角色再设计细节（需要更多制度文本与岗位画像）。

7. 对我们行动的启发

  • 把“扁平化”定义为一组可执行改造：

- 运行规则重写：谁能发起动作、谁来审批、谁能 override、异常如何升级。

- 例外设计优先：先定义 exception path 与 owner，再谈自动化比例。

- 控制面与审计：把审批链/权限/日志字段写进流程，而不是写进“管理者口头承诺”。

  • 用“项目负责制”承接扁平化后的问责：明确项目 owner 的权责边界、资源接口、评审节奏与退出机制，避免把风险推给一线。
  • 用“政策执行型场景”做组织试点：从合规/采购/共享服务等高摩擦流程入手，更容易把规则 owner、override owner 与审计边界落到制度文本。
