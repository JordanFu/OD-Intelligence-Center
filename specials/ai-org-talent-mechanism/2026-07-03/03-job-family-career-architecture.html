2026-07-03｜专题三：岗位、族群、序列的持续建设

1. 今日一句话专题判断

AI 时代岗位体系继续“双向分化”：应用/业务岗位更粗颗粒、更复合、更端到端；FDE、Applied AI、AI 安全、agent governance、模型评估、AI Infra、行业 AI 架构等护城河岗位更专业、更高溢价。新增岗位/族群/序列前，必须先判断这到底是稳定责任包，还是薪酬、保留、项目激励和市场溢价诉求。

2. 今日新增事实：只写可追溯事实

事实来源证据等级对岗位体系的含义
Workday Agent Passport 对 AI agent 做测试、验证、持续监控和撤销，绑定 OWASP LLM Top 10、NIST AI RMF、MITRE ATLAS；Cisco 是 launch partner。Workday 官方新闻稿L3agent governance 形成专业责任，但不等于所有部门都建 AI 序列。
Workday ASOR 把 agent 纳入身份、生命周期、数据权限、ROI、第三方接入和 Agent Gateway。Workday 官方页面与博客L3agent operations / agent governance 可能成为岗位族候选。
Google Cloud FDE IV Applied AI JD 要求企业 IT / AI 系统架构、MCP、多 agent、RAG、观测评估能力，美国薪资 $207k-$301k + bonus/equity。Google CareersL1FDE / Applied AI 市场定价增强。
EY FDE 岗位把角色定义为 AI & Data Architect，强调从概念到生产、客户现场交付、可复用加速器、业务价值。EY CareersL1FDE 不只是模型能力，而是客户结果责任包。
AWS 建立 $1B FDE 组织，并通过 Partner-led FDE 要求伙伴建立专属工程团队、技术门槛和交付机制。AWS 官方；AWS APNL3FDE 已从 title 走向组织接口和岗位族候选。
Payscale 2026 显示，61% 组织把 AI 技能写进角色，55% 尚未为 AI 技能调薪。Payscale CBPRL2-L3AI 技能要求快于薪酬制度，新增序列诉求常是定价诉求。

3. 今日核心判断

  1. 岗位体系主线仍是“双向分化”。可信度：高。 应用/业务岗位变宽，专家/治理岗位变深。证据来自 AWS FDE、Workday agent governance、Google/EY FDE JD、Microsoft/Deloitte/McKinsey 本地材料。
  2. agent governance 是岗位族候选，不是立刻新增全公司序列。可信度：中高。 Workday 证明该责任包有身份、权限、日志、测试、撤销和合规字段；但仍需更多企业公开职级、薪酬和晋升路径。
  3. FDE / Applied AI 的责任包正在稳定。可信度：高。 AWS、Google、EY、Anthropic、OpenAI 共同显示，这类岗位需要客户场景、架构、agent 编排、评估、部署、业务价值和能力迁移。
  4. 许多新增岗位/序列请求本质是薪酬和保留问题。可信度：高。 Payscale、EY Future of Pay、Mercer job architecture 与本地技能本位组织都支持：技能溢价、市场稀缺和关键项目不必都转化为新序列。
  5. 岗位头衔变宽不等于内部等级可以消失。可信度：高。 即使外部 title 合并，内部仍需要 level、薪酬带宽、晋升证据、职责边界和市场对标。

4. 重点案例事实还原

案例 A：Workday Agent System of Record / Agent Passport

背景。 企业 agent 开始进入 HR、Finance、Payroll、IT 等高风险流程，传统岗位架构没有现成方式管理“数字劳动力”的责任、权限和审计。

时间线。 2026-06-02 Workday 发布 Agent Passport；ASOR 官方页面说明 agent 生命周期和 Agent Gateway。

动作。 Workday 把 agent 注册、配置、激活、停用、身份权限、observability、ROI、第三方 agent 管理、测试验证和撤销写成产品机制。

机制。 这意味着岗位体系会出现新的责任组件：agent owner、workflow owner、policy owner、audit owner、risk owner、human fallback owner。

结果。 Workday 不是直接公布新岗位族，而是先把责任字段系统化。这是“先责任包，后岗位族”的典型路径。

争议和阻碍。 agent 责任归属、第三方 agent 接入、隐私、监控、合规、事故责任还需要客户案例验证。

可借鉴点。 新建岗位族前，先把 agent 的 owner、动作边界、审批阈值、日志、撤销、事故责任写进流程。

不可照搬点。 Workday 是 HR / Finance 主系统，非平台型企业不必先建完整 ASOR 岗位族，可用角色标签试跑。

案例 B：FDE / Applied AI 责任包

背景。 企业 AI 落地需要把模型能力转成客户流程、业务价值和可持续运营，不是单纯卖软件或咨询建议。

时间线。 AWS 2026 年宣布 $1B FDE 组织；AWS APN 随后推出 Partner-led FDE；Google Cloud、EY、Anthropic、OpenAI 均出现相关岗位信号。

动作。 FDE / Applied AI 岗位要求客户现场、AI 架构、多 agent、MCP、RAG、评估、观测、交付、产品反馈、复用加速器和业务价值。

机制。 这是稳定责任包：端到端结果、跨职能协调、技术判断、业务沟通、风险治理和能力迁移。

结果。 Google Cloud FDE IV 的 $207k-$301k + bonus/equity 与 Anthropic Applied AI Architecture 高薪区间说明市场已开始高价定价。

争议和阻碍。 仍缺公开统一职级路径、绩效指标、晋升规则和长期职业序列；不能直接宣布 FDE 已成熟为标准序列。

可借鉴点。 对内部类似岗位先用“责任包 + 技能标签 + 项目激励 + 市场稀缺系数”试跑。

不可照搬点。 AI 原生公司、云厂商和咨询公司的人才结构不同，普通企业不应把所有 AI 项目经理改名为 FDE。

  • 暂不形成结论，但提示我们关注：AI agent governance 可能更快形成专家方向，因为它具有风险责任、质量标准和外部合规压力。
  • 暂不形成结论，但提示我们关注：Google/EY FDE JD 是招聘信号，不等于内部完整 career ladder。
  • 暂不形成结论，但提示我们关注：Cisco 全员 agents rollout 加强岗位责任包重写，但未证明 Cisco 已新建 agent operations 序列。
  • 暂不形成结论，但提示我们关注：国内业务提出“AI 序列”时，常可能是关键人才涨薪、保留、项目奖金、资源倾斜或晋升名额诉求。

7. 对我们行动的启发

什么时候新建岗位。 长期稳定、多业务重复、端到端责任清楚、有质量/风险/决策问责、有任职资格和绩效指标、有外部薪酬对标时，才新建岗位。

什么时候新建族群。 多个相邻岗位共享能力模型、成长路径、评价标准和市场供给逻辑，例如 FDE / Applied AI 可作为候选。

什么时候新建序列。 只有当职业发展、晋升证据、薪酬带宽、专家深度与管理路径都独立时才建；序列是最高门槛。

什么时候只用技能标签。 AI fluency、提示词、AI 输出校验、自动化意识、基础 agent 使用等跨岗位、变化快、不能独立问责的能力。

什么时候用市场稀缺系数。 原岗位不变，但 AI 安全、评估、AI Infra、行业 AI 架构等能力外部市场明显加价。

什么时候用项目激励。 短期攻坚、关键客户部署、核心流程 agent 化、风险治理专项，不构成长期岗位。

什么时候用专项津贴/临时补贴。 临时值班、过渡期额外责任、阶段性风险治理、短期能力缺口。

什么时候用薪酬带宽/LTI。 长期市场价系统性上移，原带宽无法招聘或保留关键专家。

什么时候坚决不新增序列。 只是新工具、新 title、单个关键人涨薪、短期项目、单团队需求、缺评价标准、缺晋升路径、缺薪酬对标、业务想争预算或晋升名额。

8. 待验证清单与下一步搜索路径

  1. AWS / Google / EY / Anthropic 是否公开 FDE / Applied AI 的职级路径、绩效指标和晋升规则。
  2. Workday ASOR 是否出现客户级 agent owner / agent governance job family 样本。
  3. AI safety、model evaluation、agent governance 是否出现稳定薪酬带宽和职业阶梯。
  4. 国内企业是否公开 AI 序列、AI 职级、AI 津贴、AI 项目奖金或关键人才保留制度。
  5. 技能薪酬是否有 sunset、audit、pay equity 和市场稀缺系数机制。
