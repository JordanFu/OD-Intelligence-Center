# 2026-05-21｜专题三：岗位、族群、序列的持续建设

> 固定结构：一句话判断 → 新增事实 → 核心判断 → 案例事实还原 → Context → 证据地图 → 行动启发 → 待验证 → 来源索引。
> 口径：事实与判断分离；高置信判断必须能回溯到一手/权威证据。

## 1. 今日一句话专题判断

当 agent 被正式写入 运营模式（operating model），岗位/族群/序列的核心任务从“给人定岗”转向“给人‑agent 系统定接口”：**把角色（role）、KPI、owner、例外升级与验证机制做成可追踪的系统对象**，否则组织会在“agent sprawl”下重新长出隐形岗位与层级。

## 3. 今日核心判断：3–5 条（每条注明可信度、证据基础、为什么重要）

1. **岗位体系的“治理骨架”会从 岗位族群（job family） 扩展为“role + agent asset + KPI + owner”的组合对象（可信度：高）。**
   - 证据基础：SAP 把 assistants 映射到业务角色并将 KPI 追踪写进 AI Agent Hub；这相当于把“岗位接口与责任”扩展到 agent 层。https://news.sap.com/2026/05/sap-sapphire-keynote-business-ai-platform-power-autonomous-enterprise/
   - 为什么重要：没有这种组合对象，组织会出现“人负责 KPI、agent 负责动作、没人对例外与风险负责”的责任漂移。

2. **“岗位架构（job architecture） × skills graph × performance/marketplace”正在被拉到同一运行层，组织将被迫把岗位治理从静态文件升级为动态系统（可信度：中高）。**
   - 证据基础：Cornerstone 明确 Skills Architect 持续维护 岗位架构（job architecture）、从系统信号推断能力，并将其用于绩效、内部流动与组织设计。https://www.cornerstoneondemand.com/company/news-room/press-releases/cornerstone-launches-cornerstone-workforce-ai-the-intelligence-platform-for-workforce-readiness-built-to-amplify-human-potential-exponentially-with-ai/
   - 为什么重要：当技能与任务变化加速，年度一次的岗位重评会失效；需要更高频的技能/岗位信号与治理节奏。

3. **AI 时代“岗位变革诉求”更常见的本质是激励承接（技能溢价（skill premium） / 市场校准调薪（market adjustment） / 项目奖金（project bonus）），而不是必须新建序列（可信度：中高）。**
   - 证据基础：阿里云把 AI 商业指标迁移到 token/runtime 的趋势，意味着岗位价值衡量体系也会迁移；如果薪酬工具不升级，业务会更倾向用“新头衔/新序列”来争取溢价空间。https://www.nbd.com.cn/articles/2026-05-14/4392143.html
   - 为什么重要：新增序列的组织成本极高（评审、校准、带宽、晋升规则），应优先用 skills 标签与薪酬工具承接短期稀缺。

4. **职能型岗位（如 finance）正在出现“执行者→agent supervisor/governor”的结构性转向（可信度：高）。**
   - 证据基础：PwC × OpenAI 明确描述 finance professionals 的角色迁移，并强调 judgment/controls/outcomes 仍由人承担。https://www.pwc.com/us/en/about-us/newsroom/press-releases/pwc-openai-native-finance-function.html
   - 为什么重要：这要求岗位族群的能力模型与职涯梯子同步更新：从执行熟练度转向治理、例外处理与持续改进能力。

## 4. 重点案例事实还原：SAP 把 assistants 映射到业务角色并 KPI 追踪（“把岗位接口写进系统”）

> 目的：用一手材料还原“岗位/族群/序列如何与 agent 运营模式（operating model） 对齐”的可复制做法。

### 背景

- SAP 将“Autonomous Enterprise”定义为让 humans 与 AI 在关键业务工作流中协同，并提出 Autonomous Suite 覆盖多个业务域。https://news.sap.com/2026/05/sap-sapphire-keynote-business-ai-platform-power-autonomous-enterprise/

### 时间线（可追溯节点）

- **2026-05-13**：SAP Sapphire keynote 公开描述 Autonomous Suite（5 大域、200+ agents、50+ assistants）以及 AI Agent Hub 的 KPI 追踪口径。https://news.sap.com/2026/05/sap-sapphire-keynote-business-ai-platform-power-autonomous-enterprise/

### 动作（机制层）

- **role mapping**：将 assistant 映射到核心业务角色（不是“所有人一个 Copilot”，而是“角色‑任务‑agent”对齐）。
- **KPI 绑定与追踪**：每个 assistant 有定义的 KPI，并在 AI Agent Hub 跟踪（把“岗位绩效”扩展到“agent 交付”）。
- **治理与合规内嵌**：强调 built-in governance/compliance（在此案例中是叙事口径，需后续补齐具体控制点）。
（以上均来自 SAP keynote 描述）https://news.sap.com/2026/05/sap-sapphire-keynote-business-ai-platform-power-autonomous-enterprise/

### 结果（目前可观察到的）

- 将“assistant/agent”从工具层上升为可治理资产（system of record + KPI），为组织把岗位接口、owner 与责任链写清提供了可复用模板。

### 争议与阻碍（今天先不下结论，但必须盯住）

- KPI 的口径若不明确，会诱发“指标驱动的 agent 产出”而非业务结果；且对例外升级/人类校验的工作量可能被低估（与专题二/一联动）。

### 可借鉴点 / 不可照搬点

- 可借鉴：把 agent 与岗位/角色映射、把 KPI 追踪放到系统台账里；把“谁负责结果”从组织习惯变成系统规则。
- 不可照搬：SAP 的平台能力与流程标准化程度高于多数组织；落地需要先做流程/数据语义层整理。

## 7. 对我们行动的启发（方法论：什么时候新增岗位/族群/序列）

### 7.1 先做三类判断（避免“新增序列=解决方案”）

1. **这是长期战略能力（>=18 个月）吗？**
2. **这是稳定可评价的工作对象吗（可定义 KPI/质量标准/例外升级）？**
3. **这是必须用组织治理承接，还是可以用技能标签+项目角色承接？**

### 7.2 决策规则（建议口径）

- **新建岗位/族群/序列**：满足“长期关键 + 稳定可评价 + 需要明确责任链 + 需要可迁移的职涯梯子”四条件；典型：智能体治理（agent governance） owner、工作流负责人（workflow owner）、skills architect（需先定义边界与证据）。
- **只用技能标签（skills tags）**：当能力更新快、组合多、难以稳定成单一岗位；典型：行业 domain + prompt/agent orchestration + verification。
- **用薪酬工具承接稀缺（不新增序列）**：市场稀缺系数、专项津贴、项目激励、临时补贴、带宽调整；并配套 sunset 与 audit，避免永久化失衡（与专题二/四联动）。
- **坚决不新增序列**：当诉求本质是短期溢价/保留/对标竞品 offer，或岗位边界仍高度不清晰、无法定义责任与证据时。
