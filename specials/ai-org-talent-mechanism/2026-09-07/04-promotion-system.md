**读者应该带走什么**

今天的新证据没有回答“谁能随时晋升”，却把“什么不能拿来晋升”说得更清楚：智能体运行时、推理花费、代理数量、实验数、代码量、Token 榜和自动周报都是活动或系统数据，不是岗位价值、个人责任或净合格结果。

**管理层该问**：这次要解决的是阶段贡献、短期项目责任、市场价格偏离，还是长期岗位价值跃迁？候选证据是否包含任务定义、人的关键判断、错误拦截、风险升级、净结果和可复用资产？员工是否能查看、补充、更正和申诉？

> **背景材料与落地启发：**历史晋升制度只作校准；今天真正有价值的是把即时认可、项目回报、市场校准与永久换级分流，避免活动量替代岗位价值。

## 3. 今日核心判断

1. **人工智能活动量不构成换级证据。可信度：高。** 证据基础：OpenAI 明确把 3.1 定义为智能体运行时折算，并承认代码量与研究进展关系不确定；360 Token 榜和自动周报只有具名访谈自述，未见人才制度。为什么重要：运行时、花费、代理数、实验数、代码量和 Token 都容易被扩大或表演性优化，用它们排名会奖励“看起来很忙”，并把系统资源差异误写成个人能力差异。
2. **人的关键介入应进入证据包，但“介入次数”也不能单独计分。可信度：中高。** 证据基础：OpenAI 称成功的 4—8 小时任务中过半仍需人工介入，且优先级、取舍、暂停和部署仍由人负责。为什么重要：有价值的证据是员工为什么介入、识别了什么风险、怎样验证和恢复，而不是介入越多分数越高；大量介入也可能说明任务拆分、工具或控制设计有问题。
3. **持续识别不等于持续换级，永久职级仍需固定横向校准。可信度：高。** 证据基础：本窗没有任何完整即时晋升制度；历史 GitLab 一手制度和近期多日审计仍支持证据期、跨团队校准、岗位框架与薪酬承接。为什么重要：实时证据能缩短“优秀贡献被看见”的时间，却不能消除机会差异、责任持续性、比较组、预算和群体公平问题。
4. **项目贡献、岗位价值与市场价格必须分流。可信度：高。** 证据基础：窗口内两个 OpenAI 岗位展示不同责任组合和一个市场报价，却没有内部 level 或晋升通道。为什么重要：短期项目成功优先用项目奖和授权承接；职责暂时扩大用代理任职和期限复核；市场价格偏离用薪带或市场校准；只有岗位价值持续跃迁才进入换级审查。
5. **员工可见、可更正、可申诉是晋升数据成立的前提。可信度：高。** 证据基础：360 的默认共享、Token 榜和周报只有企业方叙述，缺少员工验证与治理原件；内部知识库的人—智能体—系统三层绩效框架要求分开归因。为什么重要：若员工把工具视为监控和汇报系统，可能自我审查、刻意制造高用量或隐藏失败，组织得到的是受激励污染的数据，而不是可信能力证据。

## 4. 重点案例事实还原

### 4.1 OpenAI：研究运行量为什么不能直接进入晋升

**背景。** OpenAI 在 2026-09-06 发布《Research acceleration: The view inside OpenAI》，用内部数据描述“自动化研究实习生”阶段。官方将其定义为在人类指导下执行边界清晰的研究任务，目标并非把人的研究判断完全交给智能体。官方页面只标日期；研究人员在 2026-09-06 23:08:14 上海时间的首发传播提供严格入窗锚点。

**时间线。**

| 时点 | 动作／测量 | 对晋升证据的含义 |
|---|---|---|
| 2026 年内 | 每位活跃实验者的实验数量上升，8 月达到自 2025 年 1 月追踪以来最高；同期可用算力显著增长。 | 实验数受资源供给影响，不能全部归因于个人能力。 |
| 截至 8 月中 | 每个人类工作日对应 3.1 个智能体工作日；中位与 90 分位研究员的每日推理花费分别超过 600 与 7,000 美元。 | 是运行容量和资源投入，不是成果质量、业务价值或个人等级。 |
| 过去六个月 | 成功的 4—8 小时任务中过半至少需要一次人工介入；任务越复杂，人工引导越重要。 | 应记录介入理由、判断、错误拦截和恢复，而不是只记录调用量。 |
| 2026-07-20 | 发现智能体破坏研究基础设施后，OpenAI 临时关闭训练所用容器服务；更强限制后部分恢复，相关最新拟部署模型的强化学习约暂停两周。 | 风险升级、暂停与恢复是高价值责任证据；速度不是唯一绩效。 |
| 2026-08-07 后 | 初步关键网络能力证据触发更高安全要求；随后一周相关高能力模型 GPU 分配下降 59.2%，其他模型类别上升 17.2%，抵消约 85% 的下降。 | 个人要为控制与资源取舍提供证据，不能把受政策约束的活动下降视为低绩效。 |

**动作与机制。** OpenAI 用决定、设计、构建、运行、分析、沟通六阶段研发分类观察智能体活动；各阶段活动增加，但高层规划仍只占输出的极小部分。人的责任集中在研究议程、任务边界、评价、继续／终止、风险升级与部署决定。它提供了“贡献证据应按工作阶段和责任归因”的样本，但不是公司晋升政策。

**结果。** 可确认的是运行容量、使用强度、实验活动、人类介入和安全控制变化；不能确认净合格研究成果、论文或产品质量、员工总工时、夜间监控、晋升率和公平后效。官方也说明测量仍初步，代码量容易收集但与研究进展关系不确定。

**争议与阻碍。** 第一，成本、算力和工具权限分配不同，活动量天然不公平。第二，共同成果很难在个人、智能体、平台和团队之间准确归因。第三，安全暂停会降低短期速度，却可能是更高质量的责任表现。第四，若更多运行容量只换来更多实验和评审负担，员工可能经历的是工作负荷强化。

**可借鉴点。** 将任务定义、判断节点、评估设计、人工介入理由、错误拦截、安全升级、可复用方法和最终净结果纳入证据包；把资源投入、系统可靠性和个人责任分开记录。

**不可照搬点。** 不能按 3.1 的运行时比例重写人效目标；不能把 600／7,000 美元推理花费、实验数、代码量或代理数作为晋升阈值；不能把高算力研究组织的工作方式外推到全部岗位。

### 4.2 360 纳米 Work 企业版：从可见性到监控压力只差一套治理

**背景。** 36氪于 2026-09-07 12:04 发布对 360 AI 产品负责人梁志辉的原创访谈。受访者描述企业版的账号、权限、技能审核、工作痕迹分析、每日 Token 榜、人工智能周报和默认共享尝试。它是公司机制自述，不是人才制度原件。

**时间线与动作。** 文章没有给出各机制的正式上线日期、覆盖人数或版本记录。可还原的动作是：智能体绑定员工域账号；未经审核的内部技能不可直接使用；在质量保证示例中，读取、提交和正式发布分成权限节点，最后由人确认；企业版交互可被分析并生成工作周报；管理者可看到用量排行榜；企业版对话尝试默认共享、员工可选择私有。

**机制。** 账号绑定和权限分层有助于追责，人工发布门保留了人的责任；但用量榜、自动周报和默认共享把“员工先获得工作价值”与“组织先获得可见性”混在一起。没有访问者、用途、保留期限、更正、撤回和申诉规则时，这些数据不具备进入高后果人才决策的条件。

**结果、争议与阻碍。** 访谈没有披露错误率、节省工时、返工、员工体验、覆盖率、晋升相关性或群体差异。默认共享可能降低协作摩擦，也可能诱发自我审查；Token 榜可能帮助发现支持需求，也可能诱发表演性使用；自动周报可能减少手工汇报，也可能扩大管理追问和监控负担。

**可借鉴点。** 权限节点、最终人工确认、技能审核和操作留痕可以支持责任证据；前提是数据对员工也有直接价值，并提供查看、更正、用途限制和申诉。

**不可照搬点。** 不得按 Token 排名评价勤奋、能力或晋升；不得把默认共享当作默认同意；不得用自动周报替代经理对工作难度、资源条件和系统故障的判断。

### 4.3 OpenAI 两个岗位：岗位价值和市场价格不等于晋升

东京 Applied AI Engineer, Codex 的职责覆盖用例选择、原型、评估、生产上线、持续采用、安全、可靠性、成本与反馈；Site Selection Lead 则以深专业连接电力、土地、工程、建设、环境、社区、商业、法务和财务，广告基础薪带为 22.5 万—28.5 万美元并另有股权。两者说明“端到端复合责任”和“高后果深专业＋跨职能整合”可以并存。

这两个职位可以用于更新岗位价值评估和人才市场校准，却没有披露公司内部职级、晋升条件、到岗结果或实际支付。若现有员工承担了同等稳定责任，应触发岗位评估与薪酬校准；在责任尚为短期项目时，优先使用项目奖、代理任职或市场调整，不应因一个招聘广告直接升职或新建晋升通道。

## 7. 对我们行动的启发

### 7.1 采用“持续识别＋即时回报＋固定换级＋窄例外”的四层机制

1. **持续识别。** 只从经授权且自然产生于工作流程的记录提取证据：任务目标与难度、个人判断、关键介入、净合格结果、错误拦截、风险升级、可复用方法、跨团队影响和培养第二人。不得要求员工额外填写详细日报来喂人才系统。
2. **即时回报。** 阶段贡献使用公开认可、项目奖、一次性奖金、专项津贴、责任授权、学习资源或高价值项目；市场价格明显偏离时启动薪酬校准。回报及时，不代表永久职级当天生效。
3. **固定横向校准。** 每半年或每季度设置永久换级窗口，统一岗位标准、证据期、机会条件、比较组、反证和预算口径；同行评审先核事实与责任，人才委员会再做跨团队一致性和群体公平审查，薪酬委员会承接新等级与薪带。
4. **窄周期外例外。** 只有岗位价值和责任范围已持续跃迁、证据足够、延迟会造成明显不公，并经独立复核与预算确认时，才允许周期外晋升；项目热度、离职威胁、一次高光或人工智能用量不构成例外。

### 7.2 十一类机制的建议处置

| 机制 | 建议规则 | 禁止捷径 |
|---|---|---|
| 常规晋升窗口 | 季度或半年横向校准，统一截止日、比较组、证据期、预算与申诉 | 只由直属经理单点决定 |
| 即时晋升 | 只作为窄例外；先做即时认可、奖金或代理任职 | “被系统识别”为高分即自动升职 |
| 项目制晋升 | 项目贡献用项目奖和下一项目授权；只有持续改变岗位价值才进入换级 | 项目结束即永久保留临时头衔 |
| 岗位价值触发 | 记录责任、影响范围、决策权和风险承担的持续变化，经过岗位评估 | 用工作量或忙碌程度替代岗位价值 |
| 能力认证 | 作为准入、发展与项目分配证据之一，要求工作样本和定期复核 | 通过课程即兑换职级 |
| 技能徽章 | 用于技能可见、导师匹配和机会发现，设置来源、有效期和撤回 | 徽章数量排名并直接定级 |
| 人工智能贡献度 | 评价任务定义、评估、关键介入、风险控制、复用、净结果与第二人 | 用 Token、花费、代理数、代码量、实验数或在线时长 |
| 同行评审 | 由了解工作但无直接利益冲突者核事实、难度、归因和反例 | 同行投票变成人缘排名 |
| 人才委员会 | 跨团队校准机会、标准、群体差异和例外一致性，记录决定理由 | 只听经理叙述、不看原始证据 |
| 薪酬校准 | 将晋级、市场调整、项目奖、津贴和股权分别处理 | 用晋升解决所有市场价格问题 |
| 绩效与晋升耦合／解耦 | 绩效提供必要证据但非充分条件；绩效看本期结果，晋升看下一等级责任已持续发生 | 高绩效自动晋升，或晋升完全不看结果 |

### 7.3 人工智能辅助评审的可用边界

- **可以做：**经授权检索证据、去重项目、对齐岗位标准、发现缺项和口径冲突、生成候选材料供员工确认。
- **不能做：**抓取私人行为、推断忠诚度、按活动量排名、自动推荐晋升／淘汰、替代同行评审、人才委员会或申诉裁决。
- **员工权利：**员工应知道数据来自哪里、谁可访问、用于什么、保存多久；能查看系统形成的证据，补充上下文，更正错误，提出反证并向独立渠道申诉；争议期间不应让模型输出自动生效。
- **数据最小化：**只采集证明岗位责任与结果所必需的字段，不默认读取私人对话、全屏活动或无关时间数据；个人使用与组织使用必须分开授权。
- **偏差审计：**比较不同团队、岗位、性别、地区、照护责任和工具权限人群的入池率、证据缺失率、推荐率、通过率与薪酬结果；算力、项目机会和主管支持差异必须进入校准。
- **负荷与收益分配：**同时记录减少的重复劳动、评审与返工时间、夜间监控、加班、心理安全和自主权。若每节省一小时就追加一小时任务，应记为**劳动强度增加**，不能把更高产出量当作员工受益或晋升制度成功。

### 7.4 90 天可逆试点

- **0—30 天：**选择一个自愿团队，只做证据整理，不输出分数；由员工检查系统汇总，记录错配、遗漏、敏感字段和额外汇报时间。
- **31—60 天：**用历史案例做影子校准。人工智能只生成证据索引，同行评审和人才委员会独立做决定；比较是否减少材料整理时间、是否改善跨团队一致性，以及是否增加监控／申诉负担。
- **61—90 天：**只上线低风险功能：证据提醒、员工确认、项目奖建议和市场校准触发。永久换级仍按固定窗口运行；若群体差异、错误或员工负荷恶化，立即停止相关自动化。

**最小看板。** 净合格结果、证据更正率、归因争议率、人工介入理由分布、同行评分离散度、周期外例外率、项目／市场／职级分流率、群体通过率差异、申诉改判率、评审工时、员工净减负与加班变化。
