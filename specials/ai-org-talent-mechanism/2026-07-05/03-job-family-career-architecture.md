# 2026-07-05｜专题三：岗位、族群、序列的持续建设

## 1. 今日一句话专题判断

岗位体系继续“双向分化”：应用和业务角色变得更端到端、更复合；FDE / Frontier / agent operations / AI safety / model evaluation 等专家责任包变得更深。今日新增重点不是“又出现一个新岗位”，而是 Microsoft Frontier Company 把客户现场 AI 工程从岗位族候选加厚为平台公司的正式经营单元。

## 2. 今日新增事实

1. **Microsoft Frontier Company 让 FDE 责任包经营单元化。** Microsoft 官方披露 25 亿美元、6,000 名行业与工程专家嵌入客户，共同设计、部署和持续改进 AI systems。证据等级：L3 候选。
2. **AWS FDE 是趋势互证。** AWS 官方 10 亿美元 FDE 组织嵌入客户业务、工程、安全团队，并留下 deployed systems、knowledge graphs、runbooks、architecture documentation、trained internal champions。证据等级：L3。
3. **AWS Forward Deployed AI Integrator JD 给出岗位颗粒度。** JD 写明 embedded regional Field Engineering、identify AI workflow opportunities、drive hands-on adoption、build reusable patterns、track operational KPIs、coach FE engineers。证据等级：L1。
4. **Cars24 Flatland 是反例边界。** Cars24 dropped titles / Builder 叙事说明显性 title 可取消，但未证明薪酬带宽、晋升、预算、任免、法定 title 和招聘映射已经消失。证据等级：L1-L2。
5. **国内 JD / 薪酬线索增加但制度不足。** 小红书 AI 导购/智能客服产品岗、美团 AI Agent 产品经理、DeepSeek Harness 团队与中国智能体工程化人才报告说明需求增长，但不足以证明成熟岗位族或序列。

## 3. 今日核心判断

1. **FDE / Frontier / Applied AI 责任包继续稳定。可信度：高。** 客户现场、行业知识、AI 工程、变革管理、数据治理、模型选择、持续改进和结果责任正在合并成一个高价值责任包。重要性：它是岗位族候选，但不能直接跳到序列。
2. **岗位族候选不等于成熟序列。可信度：高。** 公开材料仍缺完整职级、晋升证据、薪酬带宽、绩效指标和失败责任边界。重要性：避免 title inflation。
3. **Cars24 证明取消外显头衔不等于岗位架构消失。可信度：中高。** 只要还有薪酬、招聘定级、绩效校准、预算审批、法律职务和任免权，就仍需要内部岗位架构。重要性：扁平化不能取消治理。
4. **业务提出新岗位/序列时，本质常常是薪酬、保留、市场溢价或项目激励诉求。可信度：高。** 重要性：要先拆解诉求，再决定是否建序列。
5. **岗位分工不是单向粗颗粒化。可信度：高。** 应用层变宽，AI infra、模型评测、AI safety、agent governance、数据治理、行业 AI 架构等领域会更专业化和高溢价。

## 4. 重点案例事实还原

### Microsoft Frontier Company / AWS FDE

**背景：** 企业 AI adoption 的瓶颈不是模型访问，而是客户现场的数据、权限、流程、安全、评估、变革管理和业务结果闭环。

**时间线：** 2026-06-30 AWS 宣布 10 亿美元 FDE；2026-07-02 Microsoft 发布 Frontier Company；OpenAI Deployment Company 和 Anthropic deployment 构成旧线互证。

**动作：** Microsoft 把 6,000 名行业与工程专家嵌入客户；AWS 建立 dedicated FDE organization，并要求留下系统、知识图谱、运行手册、架构文档和内部 champion。

**机制：** FDE / Frontier 不应被理解为“工程师去客户现场”，而是跨客户流程、技术架构、治理、交付质量和能力迁移的责任包候选。

**结果：** 当前还缺职级、晋升、绩效、薪酬、失败责任、客户归属和 P&L 证据。

**可借鉴点：** 可先建立“AI deployment owner / FDE”项目角色和技能标签，用项目结果、复用资产和风险治理检验稳定性。

**不可照搬点：** 不能因为 Microsoft / AWS 有 FDE，就在内部立刻新建独立序列；本公司需要先验证需求规模和责任稳定性。

## 5. Context层

- 暂不形成结论，但提示我们关注：Microsoft 25 亿美元和 6,000 人可能包含既有 consulting / customer engineering / solution architecture 的重组包装。
- 暂不形成结论，但提示我们关注：Cars24 Flatland 若不公开薪酬、晋升、绩效、预算和任免机制，就只能证明外显 title 被取消，不能证明岗位体系被取消。
- 暂不形成结论，但提示我们关注：国内“AI 序列”诉求今天仍缺官方岗位族、薪酬带宽、晋升标准或 agent 权限治理文本，宜保留在线索层。
- 暂不形成结论，但提示我们关注：技能标签可能过度膨胀，必须设置有效期、复核周期和与项目机会/薪酬的连接方式。

## 7. 对我们行动的启发

**什么时候新建岗位：** 当责任长期稳定、可被一个人/角色端到端负责、能定义质量标准和绩效指标，并且多个团队重复需要时，才新建岗位。

**什么时候新建族群：** 当多个相邻岗位共享能力模型、市场供给、成长路径和评价标准时，才新建族群。FDE / Frontier、agent operations、AI safety、model evaluation 可作为候选，但需持续验证。

**什么时候新建序列：** 门槛最高。只有当职业发展、晋升证据、薪酬带宽、专家深度、管理路径、绩效标准都能独立闭环时，才建序列。

**什么时候只用技能标签：** AI fluency、提示词、AI 输出校验、自动化意识、基础 agent 使用等跨岗位、变化快、不能独立问责的能力，只做技能标签，接入招聘、学习、项目匹配和绩效证据。

**什么时候用市场稀缺系数：** 原岗位责任没有根本变化，但 AI safety、model evaluation、AI infra、industry AI architecture、agent reliability 等能力外部市场明显加价时，用稀缺系数，并设置复核周期、退出条件和公平审计。

**什么时候用项目激励：** 短期攻坚、关键客户部署、核心流程 agent 化、风险治理专项、数据资产专项，不构成长期岗位时，用项目奖金或专项激励。

**什么时候用专项津贴 / 临时补贴：** 临时值班、过渡期额外责任、短期风险治理、阶段性能力缺口，用津贴或临时补贴，不改岗位架构。

**什么时候用薪酬带宽调整 / 长期激励：** 某类岗位长期市场价系统性上移，原带宽无法招聘或保留关键专家时，调整带宽、LTI 或股权刷新。

**什么时候坚决不新增序列：** 只是新工具、新 title、单个关键人涨薪、短期项目、单团队诉求、业务争预算/晋升名额、没有评价标准、没有晋升路径、没有薪酬对标、只是把原岗位包装成 AI 名称时，不新增。

## 8. 待验证清单与下一步搜索路径

1. Microsoft Frontier Company 是否公开岗位族、职级、绩效、晋升、薪酬或 P&L。
2. AWS FDE / Forward Deployed AI Integrator 是否形成多地域、多等级、多职能的岗位矩阵。
3. OpenAI / Anthropic / Microsoft / AWS 是否公开 FDE / Applied AI 的职业阶梯。
4. 国内是否出现 AI workflow owner、agent supervisor、AI evaluator、AI safety lead 的稳定 JD、薪酬和晋升路径。
5. 业务部门提出 AI 新序列时，背后的真实诉求是责任稳定、市场溢价、保留关键人、项目激励还是预算争取。
