- **今日直接晋升制度新增仍为 0，无高置信新增结论。**严格窗口内没有具名公司正式披露常规窗口、即时晋升、项目制晋升、岗位价值触发、技能徽章、同行评审、人才委员会、薪酬校准与申诉的完整新规则；09:41—18:00 补扫也没有可升级材料。
- Meta Project OT 的新增价值不是证明“AI 决定晋升”，恰恰是公司回应称绩效与晋升决定仍由人；活动量、代码量和智能体产出不能跨越到个人职级判断。该项目的裁员、调岗和组织回撤链也不能被推导为晋升制度已经改变。
- 当前最稳的组合仍是 **“持续自然留证＋即时回报分流＋固定横向校准＋受控例外”**：贡献随时看见，永久等级只在责任稳定扩大、岗位长期需要、同级比较和申诉保障同时成立时变更。
- AI 在晋升流程中只适合做授权材料的检索、来源标注、缺口和矛盾检查；不应自动推断潜力、生成候选人排名、决定薪酬或裁决申诉。**原决定者与申诉复核者必须分离。**
- 人本验收必须前置：证据应来自员工已经授权的自然工作流，不新增日报、打卡或“AI 使用证明”；员工能看见、纠错和申诉；先证明个人减负与发展价值，再谈组织洞察。若节省时间全部转成更多任务，应称为**工作负荷强化**，而不是无条件生产率改善。

## 1. 今日一句话专题判断

**AI 时代不是把固定晋升窗口改成模型驱动的“随时升”，而是把识别、回报、岗位定级、薪酬与永久晋升拆开：自然工作流持续留证、短期贡献即时回报、固定窗口做人类横向校准，只为少数稳定承担更高责任者开放可申诉的受控例外。**

## 3. 今日核心判断

### 判断一：优秀贡献应随时识别，但永久晋升不应默认随时发生

- **可信度：高（历史 L3 机制＋今日零结果）。**
- **证据基础：**GitLab 历史公开制度将固定校准、周期外例外、内部流动、代理职责和薪酬审批拆开；本窗口没有第二家公司提供“全面即时晋升”制度与运行结果。
- **为什么重要：**“反馈慢”和“等级变化慢”是两个问题。一次项目、外部报价或经理留任承诺可即时回报，但若直接固化为永久等级，会跳过机会差异、岗位长期需要和同级比较。

### 判断二：AI 贡献要评净结果与控制责任，不能把活动量变成个人排名

- **可信度：高（Meta L3 机制＋历史 L2—L3 指标框架）。**
- **证据基础：**Meta 的项目链显示代码活动、智能体速度与用户价值之间不能画等号，公司回应仍由人做绩效与晋升决定；知识库“人—AI—人机系统三层绩效指标”将人的判断、AI 系统表现和共同业务结果分开。
- **为什么重要：**调用量、Token、代码量、智能体数和在线时长容易被优化，却会隐藏验证、返工、接管、安全和团队复用；若员工把个人代理体验为监控或替代工具，会自我审查，数据也不再可信。

### 判断三：绩效与晋升应“证据耦合、决定解耦”

- **可信度：中高（历史 L3 机制；今日 L1—L3 邻证）。**
- **证据基础：**绩效结果、责任、质量、复用和风险控制应进入晋升证据包；但岗位长期价值、目标级、薪酬金额、预算、生效日和申诉需分别判断。G-P 只证明厂商把高风险变更留给人工，不证明校准机制成熟。
- **为什么重要：**一次高绩效不等于责任长期扩大；预算不足也不能包装为员工“不够格”。拆开决定可以同时保护标准、薪酬公平和员工知情权。

### 判断四：晋升数据治理必须先证明员工个人价值，才可能产生可信组织洞察

- **可信度：中高（人本治理原则＋当窗隐私／节时邻证）。**
- **证据基础：**G-P 的权限继承和脱敏只是设计声明；ECB 只有自报节时，没有收益归属。内部审计反复发现额外日报、AI 打卡和人工复核会形成新的报告劳动。
- **为什么重要：**可靠链路是“个人效用→愿意且有意义地使用→可信工作上下文→有效组织洞察”。若第一步不存在，用量看板和自动证据包可能只是更快的监控，不能据此做晋升。

### 判断五：晋升速度的真实上限是校准、纠错与申诉容量

- **可信度：中高（历史 L3 机制＋今日零制度新增）。**
- **证据基础：**固定窗口的价值是聚合同级样本、机会条件、预算、薪酬和利益冲突；当前未发现新的人才委员会、同行评审或申诉制度能证明高频即时裁决仍保持公平。
- **为什么重要：**模型可以缩短材料整理时间，却不能消除冲突回避、专业异议和改判责任。没有独立申诉的“即时晋升”，只是把等待换成不透明。

### 4.1 从案例抽象出的未来组合机制

1. **持续自然留证：**从已授权的版本记录、质量门、异常、客户结果、复用和带教中取证；不要求员工额外写 AI 日报、打卡、截图或提交提示词来喂管理看板。
2. **即时回报分流：**一次成果、临时责任、稀缺技能和短期过载分别进入认可、项目奖、代理权限、限期津贴、调休／减负或市场调薪，避免都挤进永久职级。
3. **固定横向校准：**同岗位族、同目标级、同责任类型与相近机会条件下比较；业务、专业、人才和薪酬分别核验，不让直接主管单点裁决。
4. **受控例外：**仅在更高责任跨周期稳定、岗位长期需要、等待损害可证明、证据不低于常规候选时开放即时晋升；下一窗口复核例外比例、群体差异和晋升后效。
5. **决定与申诉分离：**原决定者不能主持申诉；员工能访问所用事实、纠正错误、提交反证并获得带理由的结果，改判和补救留痕。
6. **AI 辅助边界：**只做检索、来源与版本标注、证据缺口和矛盾检查；禁止潜力推断、情绪推断、候选排序、自动定级定薪和最终裁决。

## 5. 背景材料与 Context 层：弱信号、反例和冲突

> **暂不形成结论，但提示我们关注……**未来晋升的主要矛盾也许不是“窗口够不够快”，而是员工个人价值、工作证据、即时回报、永久等级和薪酬被塞进同一个决定；AI 加快材料生成后，如果用途授权、数据最小化、归因、利益冲突、解释和申诉没有同步建设，流程会更快，但证据可能更差、工作负荷更高、机会更不公平。

- **IBM Reddit 仅为 L0。**匿名帖子对 IBM Consulting 晋升是否冻结、适用对象和时间表相互矛盾，且没有绝对首发时分。它只生成 `promotion freeze + business unit + geography + budget envelope + approval chain + retroactive effective date + appeal` 的搜索路径，绝不进入公司事实层。
- **OpenAI 两个薪带不是晋升证据。**页面只说明公开报价和责任设计；地点、经验、谈判和市场时点都可能影响金额，不能反推内部 level、调薪幅度或技能溢价。
- **G-P 的“人工批准”不是程序公平。**还缺员工是否知情、谁能访问、用途是否可变、保留多久、如何纠错、如何回滚、谁承担跨法域错误；人工在环也可能只是橡皮图章。
- **ECB 的节时与晋升无直接关系。**若每周节省 3 小时全部转换为更高配额，结果是工作负荷强化；只有重复劳动、等待、无效会议和加班下降，员工获得学习、自主或休息容量，才能称个人效用改善。
- **PageUp／Sapia.ai 只属招聘邻证。**文本式、技能导向及不使用面部／声音分析是产品声明；ISO 42001 不能替代群体差异、候选人告知／退出／申诉、人工推翻和 90 天后效，更不能外推到内部晋升。
- **咨询、学术与中国公司正式晋升新增为 0。**零结果应保留，不能用页面更新、聚合播客、公众号转载或招聘标题补量；也不能断言企业内部没有改革。

## 7. 行动启发｜对我们的启发

### 管理层该问

- 这次诉求需要的是即时认可、临时责任、技能准入、市场调薪，还是稳定的永久等级变化？员工个人获得了什么价值，谁能独立纠错和受理申诉？

### 7.1 十一类机制的组合规则

| 机制 | 建议设计 | 不得自动裁决 |
|---|---|---|
| 常规晋升窗口 | 按岗位族、目标级、责任与机会条件季度／半年横向校准；准备度、岗位、预算、薪酬、生效日分审 | 不因 AI 变化快取消同级比较 |
| 即时晋升 | 仅作受控例外：跨周期承担下一层级责任、岗位长期需要、等待损害可证、多方批准、下窗复核 | 主管承诺、一次成果、外部 offer、留任压力不换级 |
| 项目制晋升 | 更准确地称“项目责任／代理职责”：先给期限、权限、项目奖、限期津贴、减负与到期回退 | 客户表扬或单次战功不自动变永久职级 |
| 岗位价值触发 | 决策权、风险、复杂度和长期责任稳定变化时先重评岗位，再评人岗匹配 | 新头衔、团队合并、旧岗撤销不自动升降个人 |
| 能力认证 | 连接学习、真实任务、项目准入、权限和限期津贴；设有效期、复证、撤销和替代路径 | 课程、考试和证书不等于胜任或晋升 |
| 技能徽章 | 只作能力可见与证据索引，标明作品、环境、授予者、有效期和员工可纠错字段 | 徽章数、排行榜、工具活跃度不形成影子职级 |
| AI 贡献度评估 | 评业务基线、人机分工、人的判断、质量、返工、接管、风险、净结果、复用、带教和员工／用户影响 | 调用量、Token、代码量、智能体数、鼠标键盘行为、模型评分不得形成晋升分 |
| 同行评审 | 专业同行核验复杂度、质量、归因、失败复盘；多人复核、冲突回避、保留少数异议 | 不做人气投票，不由单一同行定级 |
| 人才委员会 | 业务、专业、人才、薪酬分别审候选池、机会、标准、例外和分群结果；只用必要数据 | 不让经理、模型或单一高管单点裁决；不浏览无关个人数据 |
| 薪酬校准 | 市场稀缺进入薪带、市场调薪、股权、项目奖、专项／临时津贴或留任工具；资格与金额分审 | 外部报价、抢人压力或公开薪带不等于晋升 |
| 绩效与晋升耦合／解耦 | 绩效的责任、质量、影响、持续性进入证据包；岗位需要、级别、金额、预算、生效日与申诉分别裁定 | 一次高绩效不自动晋升；预算不足不伪装成不合格 |

### 7.2 先跑 90 天人本影子试点

1. **第 0—2 周｜基线与授权：**选一个岗位族，冻结现有提名、任务机会、工作负荷、薪带和群体基线；逐项说明数据来源、用途、可见者、保留期和删除／纠错权。员工不另写日报、不安装行为监控、不上交私人提示词。
2. **第 3—6 周｜自然留证：**只从正式工作流提取责任、版本、质量、返工、人工接管、风险、客户结果、复用和带教；同时记录评审工时、加班、复杂任务集中和节时去向。
3. **第 7—10 周｜同行核验：**无利益冲突的专业同行审样本，候选人先看事实并纠错；AI 只标缺口和矛盾，不打分、不排名。
4. **第 11—12 周｜影子校准：**人才委员会只输出“准备度、岗位需要、即时回报、补证／补机会”，不改变真实职级与薪酬；申诉由未参与原决定者受理。
5. **第 90 天｜停止或扩大：**比较证据缺失、人工推翻、评审总工时、群体差异、申诉改判、员工信任、重复报告、加班和实际减负。若个人效用未改善、监控感上升或评审负担转移给少数骨干，停止试点。

**停止条件：**模型参与潜力推断、候选排序或最终决定；候选人无法访问和纠错；用途、版本、人工改写或数据血缘不可追溯；原决定者主持申诉；机会不可比却横评；活动量、证书、徽章、报价或一次项目自动换级；所谓节时全部转为额外任务且不记录工作负荷强化。
