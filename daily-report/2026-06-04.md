## 三、OD 启示要点提炼

### 核心判断：今天的新增信息共同说明，AI 时代组织真正要做的是把“运行规则”写清楚

**1) 扁平化的先手动作是 authority boundary，而不是 headcount reduction 本身**  
GitLab 的落地与 Workday 的 operating model 一起说明：如果不先明确 agent 能做什么、manager 管什么、例外怎么升级，压层级只会更快放大返工和治理风险。

**2) skills 开始成为岗位、人才与晋升共享的底层语言**  
Workday 用 `Skills-Based Role Redesign` 重写角色，华为用能力图谱承接角色和技能，LinkedIn 则从外部市场层面验证 career path 正从 tenure/title 转向 skills/adaptability。这说明岗位序列和人才机制越来越不能各管各的。

**3) 高人才密度的关键从“强个体”转向“能否管理 AI 并把时间再投资”**  
BCG 给出的 47% 与 66% 两个数据很关键：更多人已在实际管理 AI，但组织没有同步定义“高价值工作该如何承接”。这使 manager support、internal mobility 和 development design 变成密度机制的主变量。

**4) 晋升机制的升级重点是 evidence schema，不是直接用 AI 自动裁决**  
Workday Agent Passport 代表的是“可审计的运行时记录”进入正式机制层。对晋升来说，这启发的是用 outcome、override、risk、quality、trust 等字段升级证据结构，而不是奖励 AI 使用量。

**5) 治理开始从“原则式口号”走向“版本化制度对象”**  
OpenAI Frontier Governance Framework 的价值不只是安全表态，而是示范企业如何把 policy、incident、external review 和 framework update 写成正式对象。未来高风险 AI 场景里，谁维护版本、谁记录例外、谁更新 guardrail，会成为正式组织责任。

**6) 很多 AI 准备度问题本质上是 person-dependent handoff 问题**  
SAP 采购 roundtable 把阻力直接落在 fragmented、person-dependent handoffs 和缺失 digital thread 上。对 shared services、采购、供应链和 HR ops 来说，AI 规模化前的关键工作往往不是继续试点，而是先清理对少数资深个体和断裂交接的隐性依赖。

**7) 国内企业可以优先观察“能力图谱是否进入正式制度”**  
华为是今天最值得持续跟踪的中国样本。关键不是发布了一套能力图谱，而是后续它是否进入招聘、认证、薪酬、内部流动和晋升规则。
