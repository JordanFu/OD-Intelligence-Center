## 三、OD 启示要点提炼

### 核心判断：本周主题——"Agent 治理从概念进入控制平面"

**1. 组织设计的基本单位正在位移**
从"岗位+部门"转向"端到端工作系统"。如果工作本身没有被拆成清晰的 handoff、决策点、升级口和度量口径，agent 就只能停留在 demo 层。OD 下一阶段最值钱的能力是**和业务一起重写跨职能流程**，而不是做 adoption campaign。

**2. Manager 角色正在被重新定义**
从"任务分派者"转为"work orchestration owner（工作编排者）"。绩效管理的评价对象也从个人执行量转向**人机系统的产出质量、升级判断与持续改进能力**。这是对现有 manager 群体最大的角色冲击。

**3. Agent 治理 = 组织设计问题，不只是 IT 问题**
ServiceNow 的控制平面、Okta 的身份架构，本质上都是把数字劳动力的权责、权限、审计、升级路径**前置进组织设计**。治理真空（agent 能做事但没人真正授权、出问题没人真正负责）将是近期高频风险。

**4. 共享服务/职能组织正在被重写为"人机混合服务系统"**
HR、法务、财务、采购等组织的设计逻辑进一步平台化。未来这些团队管理的不只是人工团队和 SOP，还包括一层不断扩张的 agent 执行系统。OD 需要把 owner、权限边界、升级路径、风险分层**前置进组织设计**。

**5. 数字身份架构将成为 OD×IT×安全的核心协作界面**
Okta 的信号非常明确：agent 身份治理（它是谁、能访问什么、代表谁行动）背后的本质是**组织权责映射**。OD、IT、信息安全需要共同定义"数字身份架构"，否则治理真空不可避免。
