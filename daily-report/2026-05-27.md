## 三、OD 启示要点提炼

### 核心判断：本周主题进一步收敛到“agent 不只是工具，而是要被纳入正式组织运行系统，而且这套系统需要语义、架构与运行时等多层基础设施”

**1. 治理对象正在从岗位扩展到“数字劳动力资产”**
Workday 的 Agent System of Record 是非常清楚的信号。组织不再只维护岗位编制和系统权限，还需要维护 agent inventory、owner、角色边界、成本、权限和退役机制。OD 要开始思考“agent 编制台账”而不仅是岗位编制表。

**2. 共享服务组织的核心能力正在从处理工单转向维护政策执行逻辑**
Sana 把 HR、Finance、IT 与差旅拉到一套 agent 执行层后，shared services 的关键不再是多快处理单据，而是政策是否被结构化、审批链是否可继承、例外是否能被正确升级。共享服务团队会越来越像“政策执行系统 owner”。

**3. Agent 治理进入运行时阶段，问责机制要前置**
Project Arc 说明 agent 一旦真正读取文件、执行命令、跨系统动作，组织必须提前定义谁批准、谁监控、谁兜底。未来很多 AI 治理问题会从模型评估转成运行时审批、审计与责任归属问题。

**4. 协作平台正在成为人机协作的默认操作台**
Slack 的方向说明，未来工作入口、agent 发现、跨职能路由和流程交接都可能收敛到协作中枢。Manager 的管理对象会从“团队成员”扩展到“团队成员 + 可被调度的 agent 组合”。

**5. Enterprise architecture 与 process mining 开始变成 agent 治理的一部分**
SAP 的信号很关键，因为它把 agent 治理和 capability mapping、流程挖掘、架构上下文连了起来。未来很多组织问题不再只是“有没有 agent”，而是这些 agent 属于哪类业务能力、嵌在哪段流程、谁拥有结果责任。

**6. 语义治理正在成为 AI scale 的前置条件**
BCG 补上了另一个容易被忽略的基础层。很多企业卡住不是因为技术买得不够，而是 customer、account、policy、case 等对象在不同部门定义不一致。没有共享语义层，agent 就很难跨系统、跨流程、跨职能稳定运行。

**7. 昨天讨论的是治理框架，今天看到的是执行基础设施开始补齐**
与 2026 年 5 月 26 日聚焦的 manager orchestration、identity 和 control plane 相比，今天的新增信号更偏底层：system of record、shared-service execution layer、runtime audit、agent browser、enterprise architecture context、semantic layer。这说明市场正在从“定义原则”走向“铺设操作层”。
