## 三、OD 启示要点提炼

### 核心判断：主题从“如何治理 agent”进一步走向“组织必须重写默认规则、接管旧流程缝隙、并把政策做成可执行系统”

**1. 真正要被重构的是组织默认假设**
McKinsey 这条信息很重要，因为它直接点破了很多企业还在用旧制度容纳新能力。只要组织仍默认“行动者只有人、绩效对象只有人、领导负责给答案”，agent 就只能被当作外挂。OD 下一步应审查决策权、审批逻辑、绩效体系和 manager 角色定义，找出仍然建立在纯人工执行假设上的制度部件。

**2. Legacy process 不再是 AI scale 的天然豁免区**
Microsoft 的更新说明，很多原先因为系统太旧、没有 API、跨平台太碎而无法自动化的流程，现在开始被纳入 agent 执行层。组织价值不只是省人力，而是终于可以把隐藏在“流程缝隙”里的大量协调劳动显性化、制度化。未来 shared services 和运营支持团队的 redesign，会越来越围绕异常升级、规则维护和端到端质量控制展开。

**3. 政策开始从文档变成工作流里的可执行约束**
SAP sustainability agents 展示了一个关键趋势：政策、合规和业务执行不再分离。过去很多组织把政策留在手册、把执行留给一线、把审查留给后台；现在 agent 可以直接把政策嵌进流程并留下审计痕迹。对 OD 来说，这会抬高“规则 owner”和“override owner”的重要性，也会让跨职能协作从材料传递转向规则共建。

**4. 组织设计焦点从 adoption campaign 转向 exception design**
三条信息放在一起看，一个共同主题非常清楚：组织不再主要缺“AI 认知”，而是缺“人机系统出错时怎么办”的机制。无论是 legacy process 自动化，还是政策内嵌执行，最终都要落回 exception path、审计边界、人工兜底和责任归属。谁有权 override，谁承担风险，谁维护反馈回路，将成为比培训覆盖率更关键的成熟度指标。

**5. 绩效和 workforce planning 也要从“人”扩展到“系统”**
如果 hybrid team 的产出越来越由人和 agent 共创，绩效就不能只看人的可见忙碌度。McKinsey 对“评价错了一半团队”的提醒很值得单独追踪。下一步可以继续收集哪些企业已开始用 system performance、exception handling quality、hybrid team improvement 等口径来重写管理评价体系。
